## 6. Tech Debt

18 items. Full structured list in the frontmatter above. The ones worth a decision before or
shortly after shipping:

**Deployment-blocking for real users:**
- **Supabase Auth Site URL still `http://localhost:3000`** on project `wrdwzychjhlpwpivfhhq`.
  Signup confirmation emails link to localhost. Needs a human change in the Supabase dashboard
  to `https://campo-gestor.pages.dev` plus allowed redirect URLs. The client-side
  `emailRedirectTo` fix is already committed and inert until this is done.

**Security:**
- **`anon` can EXECUTE the SECURITY DEFINER RPCs.** Fails closed (`42501`) because
  `is_member_of()` is false when `auth.uid()` is NULL, but the row lookup precedes the
  membership check, leaving a UUID-existence oracle (`23503` vs `42501`). Low severity against
  122-bit v4 UUIDs. Pre-existing since Phase 1. Route through `/gsd-secure-phase`.

**UX, first-impression:**
- **The landing route is an empty stub.** `dashboard_screen.dart` renders the literal text
  "Dashboard" and is the router's `initialLocation`, so every login lands on a blank screen.
  Scope-correct — no v1 requirement assigns a dashboard — but it is the first thing a user
  sees after finishing onboarding. Natural v1.1 candidate.
- **No back affordance on the animal ficha.** All three entry points use `context.go`, which
  clears the Navigator stack, and `AnimalDetailScreen` has no `leading:` fallback like its
  siblings. The user is not stranded (shell nav is present) but loses the return path.
- **`sanitary_history_section.dart` header overflows ~29px at 360px.** Pre-existing,
  D-37-locked, already flagged as a follow-up quick task.

**Process (will recur):**
- **`gsd-executor` cannot run migration plans.** Its registered tool list excludes the Supabase
  MCP tools, and local Docker/CLI is dead on this machine. Plan 07-08 returned BLOCKED without
  changing anything. Either widen that agent's tool list or mark migration plans
  orchestrator-owned at plan time.
- **Docker unavailable throughout the project.** `supabase test db` has never run; the standing
  workaround is replaying pgTAP suites verbatim against live PROD inside `BEGIN…ROLLBACK` via
  MCP `execute_sql`. It works and leaves no fixture rows, but it means the local test path is
  untested.

**Requirement text drift:**
- **ANIM-01** still reads "por (propriedade, categoria)" in REQUIREMENTS.md, but D-05
  deliberately changed numbering to global per property to fix a Phase 2 conflict with
  `UNIQUE INDEX (property_id, number)`. Implementation delivers the intent; only the wording
  is stale. Worth correcting in the archived requirements rather than carrying it into v1.1.
