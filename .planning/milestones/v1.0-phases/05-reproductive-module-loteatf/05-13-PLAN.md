<objective>
Close **WR-01** from `05-REVIEW.md` / `05-VERIFICATION.md`'s Anti-Patterns table: the ATF detail
header displays the touro's raw animal UUID instead of the readable `#<numero> — <raça>` label the
vet picked seconds earlier in the dropdown.

Root cause is on the write path, not the read path. `AtfFormDialog._submit()` treats
`bullAnimalId` and `bullName` as mutually exclusive (`atf_form_dialog.dart:115-119`): picking a
real touro sets the FK and leaves `bullName` null forever — nothing in the module ever backfills
it, and `AtfRepository` never joins `atf_batches.bull_animal_id` against `animals` on read. So
`AtfHeaderCard._buildBullValue`'s `atf.bullName ?? atf.bullAnimalId!` fallback
(`atf_detail_screen.dart:291`) always lands on the UUID for the common path.

D-05 defines the field as hybrid — FK *or* free text — and this fix keeps that: `bullAnimalId`
stays the navigation target, `bullName` becomes the display label for both branches.

Cosmetic, not data-integrity. Deliberately isolated from plan 05-12's `register_baixa` migration —
different files, different risk profile, zero `files_modified` overlap, so it can never block the
CR-01 fix.

Purpose: the header shows what the vet selected.
Output: a shared label function, a hardened read-path fallback, and the test-coverage gap the
reviewer identified.
