<objective>
Add manual encerramento: the confirmation dialog, the AppBar action, and the all-DGs-recorded banner.

Purpose: encerramento is what makes an ATF a cycle rather than a permanent list. It releases every
animal for the next protocol. D-15 makes it manual on purpose — a duvidosa awaiting reexam must not
be closed out by an automatic rule.
Output: one new dialog file plus the two encerramento affordances on the detail screen.
</objective>

Content: an `AlertDialog` whose title is a `LinearProgressIndicator` while saving and otherwise the
Copywriting Contract's encerrar-dialog title with the ATF name interpolated, rendered on one line with
`TextOverflow.ellipsis`. The content is a `SizedBox(width: 400)` — narrower than the 480 used by

default primary color — deliberately NOT the `colorScheme.error` background `BaixaDialog` applies,
because encerramento is a routine workflow step rather than data loss. Both are disabled while saving
and the confirm shows an inline `CircularProgressIndicator(strokeWidth: 2)`.

`atfActiveMembershipsProvider(atfId)`, `atfMembershipsProvider(atfId)`, and

N membership rows and the dialog must stay up until it returns. On failure show the Copywriting
Contract's encerramento-failure copy inside the dialog and leave it open with the ATF untouched. The
`finally` resets `_saving` behind an `if (mounted)` guard.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client-visible affordance → closure | Hiding the encerrar action for a non-veterinarian is a usability affordance, never an access control |
| Closure → the partial unique index | Closure is what releases each animal's uniqueness slot; a wrongly triggered closure silently frees a herd for a new protocol |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-49 | Elevation of Privilege | A reader or owner closing an ATF by calling `close_atf` directly | high | mitigate | `close_atf` re-checks `get_role(...) = 'veterinarian'` and raises 42501 (05-03); the hidden AppBar action is cosmetic |
| T-05-50 | Tampering | Double-closing an ATF, or closing one already closed, corrupting membership state | medium | mitigate | `close_atf`'s `atf_batches` lookup requires `active = true` and raises 23503 otherwise (05-03); the dialog also does not dismiss optimistically |
| T-05-51 | Repudiation | Closure erasing the roster or the DG history | high | mitigate | `close_atf` only sets `active = false` on both tables; 05-01 grants no DELETE policy and the RPC issues no DELETE (05-03) |
| T-05-52 | Tampering | Closure blocking later DG corrections, contradicting D-16 | medium | mitigate | `save_dg_records` deliberately omits the `active = true` predicate on its `atf_batches` lookup (05-03), and this plan's Task 3 asserts the DG chips stay interactive on a closed ATF |
| T-05-53 | Tampering | An automatic closure firing on the last DG, closing an ATF with a duvidosa still awaiting reexam | high | mitigate | D-15 makes closure manual; the banner is a suggestion with an explicit confirm dialog, and no code path calls `closeAtf` without user action |
</threat_model>

Flagged assumptions carried into this plan — surfaced, not silently dropped.

- **A-EDGE-REPR-03** — The spec-less edge probe returned `unclassified / unresolved` for REPR-03
  because its classifier is English-keyword-based and this project's requirement text is pt-BR. The
  "editáveis até encerramento manual" half of ROADMAP SC-3 is covered here by hand-derived assertions
  (the closed-ATF DG-chips-still-interactive test), not by probe output.
- **A-EDGE-REPR-04** — Same classification miss for REPR-04. Covered by plan 05-02's `formatPrenhez`
  tests and this plan's banner-condition tests.
- **A-BANNER-PERSIST** — Banner dismissal is session-local widget state and is lost on rebuild as well
  as on navigation, not only on revisit. 05-UI-SPEC section 3 specifies non-persistent dismissal but
  frames it as "reappears on next visit"; a rebuild-triggered reappearance is a slightly stronger
  reset than the spec implies. Flagged rather than adding persistence machinery for a dismissible
  hint.
- **A-CLOSED-READONLY** — Per D-16 a closed ATF is not read-only in the database, so the DG section
  stays editable indefinitely after closure. The Deferred Ideas list records freezing a closed ATF as
  discarded for now. If an audit requirement later demands it, that is a new trigger, not a change
  here.
</planner_assumptions>
