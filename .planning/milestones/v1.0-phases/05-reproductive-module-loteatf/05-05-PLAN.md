## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Form input → `createAtf` insert | Every field is user-supplied free text or a client-chosen id |
| Client-side role gate → visible affordances | Hiding the FAB is a usability affordance, never an access control |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-24 | Elevation of Privilege | A reader or owner creating an ATF by calling the insert directly, bypassing the hidden FAB | high | mitigate | `veterinarian_can_insert_atf_batch` (05-01) re-checks `is_member_of` and `get_role` in the RLS `WITH CHECK`; the FAB gate is cosmetic |
| T-05-25 | Tampering | A `bullAnimalId` pointing at an animal in another property | medium | mitigate | The dropdown is built from `animalListByPropertyProvider`, which is already property-scoped and RLS-guarded; a forged id would still be a valid FK, so this is accepted as low residual risk given the bull field is descriptive rather than authorising |
| T-05-26 | Tampering | An insemination date before the implantation date persisted despite the form validator | medium | mitigate | `atf_batches_date_order` (05-01) is a database CHECK; the form validator is the friendly first line only |
| T-05-27 | Tampering | An ATF created with neither a bull animal nor a bull name | low | mitigate | `atf_batches_bull_required` (05-01) is a database CHECK constraint |
| T-05-28 | Information Disclosure | The list showing ATFs from a property the user switched away from | low | mitigate | `atfListByPropertyProvider` watches `currentPropertyProvider.future` and refetches on property change, matching `animalListByPropertyProvider` |
