# Phase 5 — Reproductive Module (LoteATF): UI Design Contract

> Visual and interaction contract for creating LoteATF, registering DG in mass on mobile,
> and displaying the reproductive history block on AnimalDetailScreen.
> Generated by gsd-ui-researcher. Source of truth for gsd-planner, gsd-executor, gsd-ui-checker, gsd-ui-auditor.

## Spacing Scale

Phase 3 baseline scale, verified against `lote_form_dialog.dart`, `animal_detail_screen.dart`,
`mover_animal_dialog.dart`.

**Divergence from Phase 4 (deliberate):** 04-UI-SPEC declared `md: 12px` / `lg: 16px`, a one-off
shift introduced for the single `SizedBox(height: 12)` before the composition chips in
`_LoteHeaderCard`. Phase 5 returns to the Phase 3 token names (`md: 16px`, `lg: 24px`) — the
majority convention across the codebase. **12px is not part of this phase's scale**; the existing
Phase 4 usage stays where it is (no refactor in scope), but no new 12px gap is introduced here.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tight inline spacing |
| sm | 8px | Between form fields, KvRow separators, chip `spacing`/`runSpacing` |
| md | 16px | Card padding, dialog content vertical breaks, `ListView` outer padding |
| lg | 24px | Empty state vertical rhythm |
| 2xl | 32px | Empty state outer padding |
| 3xl | 48-64px | Empty state icon size (size token, not spacing) |

Exceptions (mobile-specific — this phase's DG screen is used one-handed in a corral):
- **DG chip row touch targets: minimum 48px height** (not the 44px floor used elsewhere) — deliberately raised for the mass-entry screen because mis-taps on livestock data are costly to correct. `ConstrainedBox(minHeight: 48)` per chip.
- **DG chip horizontal gap: minimum 8px** between the 3 chips — prevents adjacent mis-taps on a 360px-wide screen.
- Dialog content width: `SizedBox(width: 480)` — established `BaixaDialog`/`LoteFormDialog` pattern, used for `AtfFormDialog`, `EncerrarAtfDialog`, and remove-animal confirm dialog.
- `AtfAnimalSelectionScreen` and the DG mass-entry section are full-width (not dialog-constrained) — they must work at 360px viewport per the mobile constraint in this phase's brief.

## Typography

Material 3 `TextTheme` roles only — never hard-code font sizes. Matches Phase 3/4 contract exactly (no new roles introduced).

| Role | Flutter TextTheme | Size | Line Height | Weight | Usage in Phase 5 |
|------|-------------------|------|-------------|--------|-------------------|
| Body | `bodyMedium` | 14sp | 1.43 (M3 default) | 400 | Secondary lines (subtitle text, muted labels), explanation text in dialogs |
| Label | `bodyLarge` | 16sp | 1.50 (M3 default) | 400 (600 for numeric emphasis) | List item primary text, animal number `#N` (w600), DG chip labels |
| Heading | `titleMedium` | 16sp | 1.50 (M3 default) | 500/600 | Section labels ("Composição", "Registrar DG"), card titles, dialog titles |
| Display | `headlineSmall` | 24sp | 1.33 (M3 default) | 400 | Not used — no full-page display headers introduced this phase |

Line heights are the Material 3 `TextTheme` defaults — do not override `height:` on any of these
roles. Listed explicitly here so the DG row's fixed 48px min-height is verifiable against the
rendered line box (`bodyLarge` at 16sp × 1.5 = 24px, leaving 12px vertical padding per chip).

**DG chip label exception:** chip text uses `bodyLarge` at `FontWeight.w600` (not the default 400) — sunlight-legibility requirement for the mobile mass-entry screen. This is the one place this phase deviates from default chip typography (Phase 3's EC chips use unstyled `ChoiceChip` default text).

## Color

All colors derive from `ColorScheme.fromSeed(seedColor: Color(0xFF4A6741))`. No new seed, no hex literals except where a semantic status color is hardcoded following the exact precedent set in `AnimalInfoCard`'s status badge (Phase 3).

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` | Scaffold background — `ReproducaoScreen`, `AtfDetailScreen`, `AtfAnimalSelectionScreen` |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | Cards (ATF header card, composition card), list item backgrounds |
| Accent (10%) | `colorScheme.primary` | See explicit reserved-for list below |
| Destructive | `colorScheme.error` | "Não-prenha" DG chip (see semantic mapping below) — reused as negative-outcome color per Phase 3 precedent, not a delete action here |

**Accent (`colorScheme.primary`) reserved for — explicit list:**
1. FAB "Criar ATF" (role-gated veterinarian)
2. `FilledButton` primary actions: "Criar ATF" (AtfFormDialog submit), "Adicionar N animais" (AtfAnimalSelectionScreen confirm), "Salvar DGs" (batch save), "Encerrar" (EncerrarAtfDialog confirm)
3. Active `NavigationRail`/`NavigationBar` destination indicator (unchanged, existing)
4. Selected `FilterChip` in category filters (reused from `/animais` filter row per D-06)
5. `LinearProgressIndicator` / `CircularProgressIndicator` during RPC calls
6. "Prenha" DG chip selected state — see semantic mapping below (accent doubles as the positive-outcome color, matching the "Ativo" status badge convention)
7. % prenhez `LinearProgressIndicator` (DG completion progress bar) fill color

**DG chip semantic color mapping** (new this phase — extends the status-badge precedent from `AnimalInfoCard`, which already hardcodes `Colors.green.shade100/800` for "Ativo" rather than using `colorScheme.primary`):

| Result | Selected background | Selected text | Rationale |
|--------|---------------------|----------------|-----------|
| Prenha | `colorScheme.primaryContainer` | `colorScheme.onPrimaryContainer` | Positive outcome — accent register, mirrors "Ativo" badge's positive-status role |
| Não-prenha | `colorScheme.errorContainer` | `colorScheme.onErrorContainer` | Negative outcome — reuses the exact tokens `AnimalInfoCard` already uses for "Arquivado" (negative-status, not a destructive-action trigger) |
| Duvidosa | `colorScheme.tertiaryContainer` | `colorScheme.onTertiaryContainer` | Pending/warm outcome — mirrors the "Vendido" warm-tertiary badge convention from Phase 3 |

Unselected chip state: `OutlineInputBorder`-style outline, `colorScheme.outline` border, `colorScheme.onSurface` text — same visual language as unselected `ChoiceChip` in `AnimalEditDialog`'s EC row.

**Accent must NOT appear on:** regular `ListTile`/`Card` borders, `AppBar` background, secondary actions (`TextButton`, `OutlinedButton`), the "Mostrar encerrados" toggle (uses default `Switch` — no primary override, matches "Mostrar arquivados").

### 1. ReproducaoScreen (replacement — `/reproducao` shell branch)

**Purpose:** List of LoteATFs for the active property (D-01). Replaces the placeholder at `lib/features/reproducao/presentation/reproducao_screen.dart`.


- Trailing (only when `!atf.active`): `Chip` badge "Encerrado" using `colorScheme.surfaceContainerHigh` + `onSurface` (neutral, not error — closing a cycle is not a failure state).

- Heading: `"Nenhum ATF cadastrado"` (`titleMedium`)
- Body: `"Crie um ATF para iniciar um ciclo reprodutivo."` (`bodyMedium`, `onSurface` 60%)

**Empty state — toggle off hides all remaining (property has only encerrados):**
- Same icon/size, heading `"Nenhum ATF ativo"`, body `"Ative 'Mostrar encerrados' para ver o histórico."`

### 2. AtfFormDialog (new — modal dialog)

**Purpose:** Create a new LoteATF with header fields only (REPR-01, D-01, D-05). Composition is added afterward via `AtfAnimalSelectionScreen` (D-06/D-08) — this dialog does NOT select animals, unlike `LoteFormDialog` which bundles composition inline. Rationale: animal selection is too complex (search, disabled rows, avulsos) for `AlertDialog` real estate.

**Dialog width:** 480px, `AlertDialog` pattern matching `LoteFormDialog`.

**Form fields (in order):**
1. **Nome do ATF** — `TextFormField`, `OutlineInputBorder`, required, autofocus. Label `"Nome do ATF *"`.
2. **Data de implantação** — `TextFormField` with date picker suffix icon (`showDatePicker`), required, format `DD/MM/AAAA`, defaults to today.
3. **Data de inseminação** — same pattern, required. Validator: must be `>=` data de implantação.
4. **Touro** — hybrid field per D-05:
   - `DropdownButtonFormField<String?>` populated with active touro animals of the property (`kCategoryLabels['bull']` category), items formatted `"#N — Raça"` or `"#N"` if no breed.
   - Last item: `"Outro / sêmen externo"` (`value: '__other__'`).
   - When `'__other__'` selected: reveal a `TextFormField` below, label `"Nome do touro / identificação do sêmen"`, required when this path is chosen.
   - Validator (dialog-level): at least one of `bullAnimalId` or `bullName` must be set. Error: `"Selecione um touro ou informe sêmen externo"`.
5. **Observação** — `TextFormField`, optional, `maxLines: 3`.

**Actions:**
- `TextButton` "Cancelar"
- `FilledButton` "Criar ATF" (disabled during save, `CircularProgressIndicator(strokeWidth: 2)` inside button while saving — matches `AnimalEditDialog`/`LoteFormDialog` pattern)

**On success:** RPC creates the `atf_batches` row with zero animals. Dialog pops with the new ATF id. Caller (`ReproducaoScreen`) navigates directly to `/atf/:atfId`, where the empty composition state prompts "+ Animais" (D-06/D-08 continuity).

### 3. AtfDetailScreen (new — `/atf/:atfId`, root-level GoRoute per D-02)

**Purpose:** ATF header, composition management, mass DG entry, and manual encerramento. The single screen where REPR-02, REPR-03, REPR-04 happen.

**Layout:**
```
AppBar: atf.name + back button + [Encerrar icon action, role-gated, only when atf.active]
Body (ListView, padding: EdgeInsets.all(16)):
  ├── AtfHeaderCard
  ├── SizedBox(height: 16)
  ├── [EncerrarBanner — only when atf.active && allAnimalsHaveDg]
  ├── SizedBox(height: 16)
  ├── _CompositionSection (title "Composição" + count, "+ Animais" button if atf.active)
  ├── SizedBox(height: 16)
  └── _DgSection (title "Registrar DG", session date field, per-animal chip rows, "Salvar DGs" button)
       — DG section is ALWAYS editable (active or encerrado) per D-16; only composition
         editing and the Encerrar action are gated by atf.active.
```

**AtfHeaderCard:**
- `Card`, `colorScheme.surfaceContainerHighest`, padding 16
- Row: `[icon Icons.favorite_border]` `[atf.name, titleMedium]` `[Spacer]` `[status badge: "Ativo" or "Encerrado"]`
- KvRows (same `_KvRow` component as `AnimalInfoCard`, label width 120): Data de implantação, Data de inseminação, Touro (tappable → `/animais/:id` if `bullAnimalId` set, else plain text), Observação (if present)
- % prenhez display per D-18 format, `bodyLarge` weight 600, `colorScheme.primary`
- `LinearProgressIndicator` DG-completion bar below the % text

**EncerrarBanner** (D-15 — alert when all animals have DG):
- `MaterialBanner` or `Container` styled as a banner: `colorScheme.tertiaryContainer` background, padding 16, rounded corners 12
- Text: `"Todos os animais têm DG registrado."` (`bodyMedium`, `onTertiaryContainer`)
- Action: `TextButton` "Encerrar ATF" → opens `EncerrarAtfDialog`
- Dismissible with an `IconButton(Icons.close, tooltip: 'Dispensar aviso')` — dismissal is session-local (does not persist; banner reappears on next visit while the condition holds). This is the discretionary "mecânica exata do alerta" resolved as: persistent banner, not a one-shot SnackBar, because the vet may leave the corral mid-session and return later.

**_CompositionSection:**
- Header row: `"Composição"` (`titleMedium`) + `"(N animais)"` muted + `Spacer` + `OutlinedButton.icon(Icons.add, "Animais")` — only when `atf.active`, opens `AtfAnimalSelectionScreen`
- List: one row per active membership — `#42 · Vaca` (`bodyLarge`, number w600) + trailing `IconButton(Icons.close, tooltip: 'Remover do ATF')` to remove, only rendered when `atf.active && !hasDgForThisAnimal` (D-08). When a membership cannot be removed (has DG), no icon is shown (absence, not disabled — matches the established role-gate convention of not showing disabled affordances).
- Tapping a row navigates to `/animais/:id` (consistent with every other animal-list-tile pattern in the app).

**Remove-animal confirm dialog** (small, reused pattern):
- `AlertDialog`, title `"Remover #42 do ATF?"`, body `"O animal deixa de fazer parte deste ciclo."`, actions `TextButton "Cancelar"` + `FilledButton "Remover"` (default primary color — not destructive-red, since this is a correction action, not data loss).

**_DgSection** (D-10, D-11, D-12 — the mobile-critical mass-entry list):
- Header: `"Registrar DG"` (`titleMedium`)
- Session date field: `TextFormField` with date picker suffix, label `"Data da sessão"`, defaults to today, full width. Applies to all rows saved in this batch unless overridden per-row.
- One row per animal currently active in the ATF (same list as composition, not a separate query):
  ```
  Row:
    [#42 · Vaca]  (fixed-width ~90px, bodyLarge w600 for number)
    [3 chips: Prenha | Não-prenha | Duvidosa]  (Expanded, spaceBetween, min 48px height each)
    [IconButton Icons.event, tooltip: 'Alterar data deste animal']  (opens date picker for THIS animal only)
    [IconButton Icons.notes, tooltip: 'Adicionar observação']  (expands a TextFormField below the row)
  ```

**Icon-only rule (all screens in this phase):** every `IconButton` declared above MUST carry a
`tooltip:` in pt-BR. The tooltip is the accessible label on Flutter web (it feeds the semantics
tree) and the hover affordance on desktop. No icon-only action ships without one.
- Rows for animals that already have a most-recent DG show that chip pre-selected (using the semantic colors above). Tapping a different chip does not overwrite history — it stages a NEW DG record for that animal (D-12: multiple DGs per animal per ATF are additive, most-recent wins for display/%).
- Only rows whose chip selection changed relative to the currently-displayed value (or newly set from blank) are included in the batch save payload — unchanged rows are skipped, avoiding redundant DG rows on re-save.
- Footer: `FilledButton` "Salvar DGs" — full width, disabled when zero rows changed. Shows `LinearProgressIndicator` pattern during the RPC call (button becomes disabled + inline spinner, matching `LoteFormDialog`'s batch-save treatment, not the dialog-title-replacement pattern since this is not a dialog).
- On success: `SnackBar` "DGs registrados." Providers invalidated: this ATF's detail provider (recomputes % prenhez), the ATF list provider, and (if any affected animal is currently open) that animal's reproductive-history provider.
- On error: `SnackBar` "Erro ao salvar DGs. Tente novamente." Staged selections are NOT cleared — vet does not need to re-mark the whole rebanho.

**Mobile/legibility notes for `_DgSection` (explicit — this is the phone-in-corral screen):**
- Single column, no horizontal scroll at 360px width.
- Chip minimum touch target 48×48px (raised from the app's usual 44px floor — see Spacing exceptions).
- Chip selected state uses solid `*Container` fill + `bold` text (`FontWeight.w600`) for sunlight contrast, not a subtle tint.
- Animal number/category label uses `bodyLarge` (16sp), not `bodyMedium` (14sp), for readability at arm's length.
- No swipe gestures, no long-press — single tap only (gloved-hand, one-handed operation).

### 4. AtfAnimalSelectionScreen (new — full-screen, pushed via `Navigator.push`, not a GoRoute)

**Purpose:** Implements D-06/D-07/D-09 — pick a base lot, review pre-marked vaca/novilha animals, deselect as needed, add avulsos from other lots. Used both right after ATF creation and later via "+ Animais" (D-08).

Not a GoRoute because it is a transient selection workflow with no deep-link requirement (mirrors how dialogs are pushed, just full-screen instead of a modal — full-screen chosen because the content (search + filter + long checklist) does not fit `AlertDialog` real estate, especially at 360px width).

**Layout:**
```
AppBar: "Adicionar animais" + back button (X icon, confirms discard if selection changed —
        reuse the same "unsaved changes" caution as any form, no separate spec needed)
Body (Column):
  ├── _LoteBaseDropdown: "Lote base" — DropdownButtonFormField, selecting a lot loads
  │     its active vaca/novilha animals, all pre-checked (D-06)
  ├── Checklist of that lot's eligible animals (CheckboxListTile per row)
  │     — disabled rows (D-07): grey text, no checkbox interaction, trailing reason text
  │       "já em ATF Primavera"
  ├── Divider + "Avulsos" section label (titleMedium)
  ├── SearchBar + FilterChip row (reused from AnimaisScreen, filters LOCKED to
  │     categoria ∈ {vaca, novilha} — D-09: UI never shows touro/terneiro here)
  ├── Checklist of matching avulso animals (CheckboxListTile, same disabled-row treatment)
  └── Bottom sticky bar: "N animais selecionados" (bodyMedium) + FilledButton "Adicionar animais"
FAB: none (bottom sticky bar replaces it)
```

**Disabled row format** (D-07, exact copy): `"#42 · Vaca — já em ATF Primavera"` — `ListTile.enabled: false`, text color `onSurface` 38% alpha (Flutter's automatic disabled treatment), trailing reason text same muted color.

**Empty state — chosen lot has no eligible animals:**
- Inline message (not full-screen empty state, since the avulsos section is still usable): `"Nenhuma vaca ou novilha neste lote."` (`bodyMedium`, `onSurface` 60%), shown in place of the checklist.

**On confirm ("Adicionar animais"):** RPC adds the selected animals to the ATF (SECURITY DEFINER, atomic per D-21). On success, pops back to `AtfDetailScreen`, which invalidates its composition provider. `SnackBar`: `"N animais adicionados ao ATF."`

### 5. EncerrarAtfDialog (new — modal confirmation dialog)

**Purpose:** Manual closure (D-15). Same structural template as `BaixaDialog`.

**Dialog width:** 400px.

**Content:**
- Title: `_saving ? LinearProgressIndicator() : Text('Encerrar ATF "[nome]"?')`
- Body: `"Esta ação libera os animais para participar de um novo ciclo. O histórico é preservado e correções de DG continuam possíveis depois de encerrado."` (`bodyMedium`)
- If DGs are still pending (banner condition not met — user triggered this from the AppBar action, not the banner): additional warning line in `colorScheme.tertiary`: `"Ainda há N animal(is) sem DG registrado."`

**Actions:**
- `TextButton` "Cancelar"
- `FilledButton` "Encerrar" (default primary color — matches the remove-animal dialog's non-destructive-red choice; encerramento is a routine workflow step, not data loss)

**On success:** pops with `true`. `AtfDetailScreen` invalidates its provider and the ATF list provider. `SnackBar`: `"ATF encerrado."`

## Interaction Contracts

### Role Gate
- FAB "Criar ATF": visible only when `role == 'veterinarian'`. Same `_canEdit` pattern as Phases 3–4.
- "+ Animais" button, remove-animal icon, "Encerrar ATF" (AppBar action + banner action), "Salvar DGs" button: all absent (not disabled) for non-veterinarian roles.
- DG chips themselves: read-only (non-tappable, no visual "disabled" treatment needed — just omit the `onSelected` callback) for non-veterinarian, since D-13 already restricts DG entry to the mass-entry screen regardless of role, and only veterinarians reach this screen's edit affordances.

### Navigation
- `/atf/:atfId` is a root-level `GoRoute` (D-02), added to `AppRoutes` as `atfById = '/atf/:atfId'` template + `static String atfDetail(String id) => '/atf/$id'` helper — mirrors `loteById`/`loteDetail`.
- `AtfAnimalSelectionScreen` is pushed via `Navigator.push(MaterialPageRoute(...))`, not a GoRoute — no deep-link requirement, transient workflow.
- Reproductive history rows navigate via `context.go(AppRoutes.atfDetail(atf.id))`.
- Back button always `context.pop()` for GoRouter routes, `Navigator.pop()` for the pushed selection screen — consistent with the existing split.

### Forms
- All dialogs (`AtfFormDialog`, `EncerrarAtfDialog`, remove-animal confirm): `AlertDialog` pattern, `SizedBox` width constraint, `LinearProgressIndicator` replaces title during save, `FilledButton`/`TextButton` action pair — verbatim `LoteFormDialog`/`BaixaDialog` template.
- Date pickers: Flutter's built-in `showDatePicker` (no new package) — format `DD/MM/AAAA` via `intl`.
- `ref.invalidate(...)` on every successful mutation, matching the established post-success pattern.

### DG Batch Save
- Only changed rows are sent to the RPC (see `_DgSection` above) — reduces payload and avoids spurious `dg_records` rows on re-save.
- The RPC is atomic (D-21): either all staged DGs in the batch save or none do. On partial-network failure, no partial DG set is left behind.
- Staged (unsaved) chip selections persist in local widget state across a save failure — vet does not lose in-progress marking on a bad connection in the field.

### Snackbar
- Success confirmations ARE shown in this phase (unlike Phase 3/4's "navigation serves as confirmation" convention) because the DG save and animal-add flows do NOT navigate away — the vet stays on `AtfDetailScreen`/`AtfAnimalSelectionScreen`, so an explicit confirmation is the only feedback. Error: same `ScaffoldMessenger` pattern as established.
