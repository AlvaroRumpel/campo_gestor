`add_animals_to_atf(p_atf_batch_id uuid, p_animal_ids jsonb) RETURNS void` —
`LANGUAGE plpgsql SECURITY DEFINER SET search_path = public`. Select `property_id` from `atf_batches`
into a local variable for `p_atf_batch_id` where `active = true` and `deleted_at IS NULL`; raise with
ERRCODE `23503` when null (not found or already closed). Raise with ERRCODE `42501` when
`is_member_of(v_property_id)` is false, and again with `42501` when
`get_role(v_property_id) <> 'veterinarian'::role_enum`. Then bulk-INSERT into
`animal_atf_memberships (animal_id, atf_batch_id, active, property_id)` selecting from
`jsonb_array_elements_text(p_animal_ids)` cast to uuid, with `active` true and the derived
`property_id`. Do NOT re-check the animal's category or property inside this function — that is
`trg_atf_membership_valid`'s job and it fires on this INSERT (RESEARCH Pitfall 2 explicitly warns
against duplicating it here). Do NOT add `pg_advisory_xact_lock` (Pitfall 3). The `p_animal_ids`
parameter is `jsonb` rather than `uuid[]` so the Dart `List<String>` serializes through the
already-proven path used by `create_lot_with_animals`.

`remove_animal_from_atf(p_atf_batch_id uuid, p_animal_id uuid) RETURNS void` — same header and same
three guards. Then raise with ERRCODE `23514` when a `dg_records` row already exists for that
(atf_batch_id, animal_id) pair, with a message stating that an animal with a DG cannot be removed and
that encerramento is the way to close it out (D-08). Otherwise `DELETE` the membership row for that
pair where `active = true`. This is a hard DELETE, not a soft `active = false` — deliberately, and it
is the single most important distinction in this migration: `save_dg_records` (Task 2) distinguishes
"removed before any DG, never accept a DG again" from "closed, correction still allowed" purely by
whether the membership row EXISTS. Write that rationale as a comment above the DELETE so a later
reader does not "harmonize" it into a soft deactivation.

`close_atf(p_atf_batch_id uuid) RETURNS void` — same header and guards, with the `atf_batches` lookup
requiring `active = true` so closing an already-closed ATF raises `23503`. Then `UPDATE atf_batches
SET active = false` for the id, and `UPDATE animal_atf_memberships SET active = false` for every row
of that batch where `active = true`. The second UPDATE is what frees each animal's slot in
`animal_atf_memberships_active_idx` for the next cycle (D-16); the rows stay, so history and DG
correction survive.

End each function with the `REVOKE ALL ON FUNCTION ... FROM public;` and
`GRANT EXECUTE ON FUNCTION ... TO authenticated;` pair, matching `move_animal_to_lot`.

`save_dg_records(p_atf_batch_id uuid, p_records jsonb) RETURNS void` —
`LANGUAGE plpgsql SECURITY DEFINER SET search_path = public`. Select `property_id` from
`atf_batches` for `p_atf_batch_id` — note the deliberate absence of an `active = true` filter here,
unlike the three functions in Task 1, because D-16 requires DG correction to stay possible after
encerramento. Raise `23503` when not found. Apply the same `is_member_of` and veterinarian-role
guards with ERRCODE `42501`.

Loop over `jsonb_array_elements(p_records)`. Per record, extract `animal_id` (cast to uuid), `result`,
`exam_date` (cast to date), and `observation`. Raise with ERRCODE `22023` when `result` is outside the
three allowed values. Then apply the existence guard: raise with ERRCODE `23503` when no
`animal_atf_memberships` row exists for the (p_atf_batch_id, animal_id) pair — checking existence
only, deliberately NOT filtering on `active`. That single condition is what makes all three
deactivation paths behave correctly: a D-08 removal hard-deleted the row so a DG is refused, while a
D-16 closure and a D-19 baixa left the row present so a correction is accepted. Write that as a
comment. Then INSERT into `dg_records (property_id, atf_batch_id, animal_id, result, exam_date,
observation)` using the derived property id. Only INSERT — never UPDATE or DELETE an existing DG row;
D-12 makes the history additive and the most recent record wins at read time. Because the whole
function body is one transaction, a bad record anywhere in the batch rolls the entire batch back,
which is the atomicity 05-UI-SPEC's DG Batch Save contract requires.

`register_baixa(p_animal_id uuid, p_reason text, p_date date, p_observation text DEFAULT NULL)
RETURNS void` — same header. Select `property_id` from `animals` for `p_animal_id` where
`deleted_at IS NULL`; raise `23503` when null. Apply the veterinarian-role guard with `42501`. Raise
with ERRCODE `22023` when `p_reason` is outside the three values `sale`, `death`, `discard` (the

the existing value, guarded by `WHERE id = p_animal_id AND deleted_at IS NULL`; follow with an

also report success. Do NOT add a second UPDATE against `animal_atf_memberships` here — plan 05-01's
`trg_animals_baixa_deactivates_atf` trigger fires on this UPDATE and performs the D-19 deactivation on
every access path, including a raw PostgREST PATCH that never reaches this function. Note that in a
comment so the omission reads as deliberate.

Close both functions with the `REVOKE ALL` / `GRANT EXECUTE ... TO authenticated` pair.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated caller → SECURITY DEFINER function | Inside the function body RLS is bypassed; every check the caller should have faced must be written explicitly |
| Function parameters → SQL | All parameters are attacker-controlled, including the jsonb payload's shape and every value inside it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-13 | Elevation of Privilege | `search_path` hijack against any of the five SECURITY DEFINER functions | high | mitigate | Every function declares `SET search_path = public` (Tasks 1 and 2), matching `move_animal_to_lot` |
| T-05-14 | Elevation of Privilege | A reader- or owner-role member calling `save_dg_records` or `close_atf` directly | high | mitigate | Each function re-checks `is_member_of` and `get_role(...) = 'veterinarian'` server side and raises SQLSTATE 42501; the UI role gate is not relied upon |
| T-05-15 | Elevation of Privilege | A client passing a `property_id` for a property it does not belong to | high | mitigate | No function accepts a property parameter; every one derives it from the referenced `atf_batches` or `animals` row (acceptance criterion in Task 1) |
