  <action>
    Create `lib/features/sanitario/presentation/sanitary_history_section.dart` holding one private
    card shell and two public widgets.

    The private shell is a `Card` with a 12-pixel rounded border, an outline side at 38 percent alpha
    and the plain surface colour — the exact shape `_ReproductiveHistorySection` and
    `_PlaceholderSection` already use — with 16-pixel padding. Its header row is the locked section
    label in the title role, a spacer, and a compact `Switch` carrying the locked reversed-toggle
    label. Below it, an eight-pixel gap, then the async body it is handed. It owns the toggle state,
    so each placement gets its own switch with no shared provider — the toggle is a per-surface view
    preference, not application state.

    Public widget one — the animal variant, a `ConsumerStatefulWidget` taking an animal id. It
    watches `sanitaryHistoryByAnimalProvider` for that id and renders through the shell. This is the
    D-37 contract: it must compile and render with nothing but an animal id, so Phase 8 can drop it
    into a different screen unchanged. Its rows use the locked animal-ficha format — dose name, an
    em-dash, the date formatted day/month/year, then the frozen lote name after the locked lote
    prefix. Its empty sentence is the locked no-sanitary-history-for-animal copy.

    Public widget two — the lote variant, a `ConsumerStatefulWidget` taking a lot id. It watches
    `sanitaryApplicationsByLotProvider` for that id. Its rows use the locked lote-history format —
    date, dose name, the animal count through `Intl.plural`, and the total cost appended only when
    the frozen total is non-null. Its empty sentence is the locked no-applications-in-this-lote copy.

    Shared body behaviour for both variants: apply `visibleApplications` with the shell's toggle
    value, then take at most ten rows for rendering, then render each as an `InkWell` navigating to
    the application detail route. When the visible list is longer than ten, append a `TextButton`
    with the locked "Ver todas" label navigating to the sanitary module route with a query parameter
    carrying this animal id or this lot id, which the module screen in 06-10 reads to seed its
    filters. Compute the "more than ten" condition from the full visible list, not from the rendered
    slice, so the action's presence is not itself an artefact of the cap.

    Row rendering: single line, ellipsis overflow. A row that is itself a reversal or that appears in
    `reversedApplicationIds` renders with line-through decoration and a trailing badge — the reversed
    badge on the error-container tokens for a reversed original, the reversal badge on the neutral
    high-container tokens for a reversal record. Those rows are only reachable when the toggle is on.

    Async states: a section-local centred spinner while loading, and the variant's error sentence on
    failure — the animal variant uses the locked sanitary-history load-failure sentence, the lote
    variant the generic one. Neither may propagate an error past the card.

    Render no count label on either variant.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frozen snapshot → rendered history row | The whole point of the snapshot is that rendering must not consult live records |
| Cross-property containment lookup | An animal id from another property must not resolve applications |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-11 | Tampering | history row silently showing current instead of frozen attributes | medium | mitigate | Neither variant reads an animal, lot or dose model; every value in a row comes from the frozen application row, and the acceptance criteria assert that no such model is referenced in the file |
| T-06-06 | Information Disclosure | containment lookup returning another property's applications | high | mitigate | The lookup runs through the SELECT policy scoped by `is_member_of(property_id)`, so a foreign row is filtered server-side before the containment predicate matters |
| T-06-15 | Information Disclosure | a voided application counted as if it still applied | medium | mitigate | `visibleApplications` hides both the reversed original and its reversal by default, and the section renders no count or total derived from the capped slice |

ASVS level 1; blocking severity is high. No new packages, so no supply-chain row.
