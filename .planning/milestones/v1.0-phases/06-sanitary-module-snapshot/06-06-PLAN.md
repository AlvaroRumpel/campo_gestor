  <action>
    Create `lib/features/sanitario/presentation/dose_form_dialog.dart` with a
    `ConsumerStatefulWidget` named `DoseFormDialog` taking an optional existing `Dose`. When that
    argument is present the dialog is in edit mode and its controllers seed from the passed row;
    when absent it is create mode. One widget, one code path, one difference.

    Render an `AlertDialog` whose content is wrapped in a `SingleChildScrollView` inside a
    `SizedBox` constrained to 480 pixels wide, matching the established form-dialog token. The scroll
    wrapper is what keeps the form usable at a 360-pixel width with the keyboard open.

    Six fields in order, using the exact labels from the Copywriting Contract:
    the commercial name — required, autofocus, single-line, validator returning the locked
    name-required message on a blank trimmed value;
    the active ingredient — optional, single-line;
    the per-kg dosage — required, with the project's existing decimal input formatter and pt-BR comma
    handling, validator returning the locked dosage-required message when blank or unparseable;
    the per-UA dosage — a disabled `TextFormField` whose controller is rewritten on every change of
    the dosage field, its text styled in the primary colour and the medium body role to signal
    "calculated, not entered";
    the per-kg cost — optional, same decimal formatter;
    the per-UA cost — a disabled `TextFormField` rendered only when the cost field parses to a
    number, and removed from the tree entirely when the cost field is blank.

    Read the UA factor from the property exposed by `currentPropertyProvider`, falling back to 400
    when the property has not resolved, and feed it plus the parsed per-kg value into `dosagePerUa`
    and `costPerUa`. Do not re-implement either formula here.

    Parse the pt-BR decimal input by replacing the comma with a period before `double.tryParse`, and
    treat an unparseable dosage as a validation failure rather than as zero. A blank cost parses to
    null, not to zero — that null is what travels to the repository and to the omitted rows
    downstream.

    Add listeners on the two editable numeric controllers that call `setState`, so both computed
    fields update on every keystroke.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04 | Elevation of Privilege | dose created or edited by a non-veterinarian | high | mitigate | The dialog is only opened from role-gated entry points, and `veterinarian_can_insert_dose` / `veterinarian_can_update_active_dose` reject the write server-side regardless |
| T-06-12 | Tampering | a malformed numeric input persisting as a silent zero | medium | mitigate | An unparseable dosage fails validation rather than defaulting; a blank cost persists as null, not zero, so no fabricated price can be frozen into a permanent application row |
| T-06-06 | Information Disclosure | writing a dose into another property | high | mitigate | The property id comes from `currentPropertyProvider`, and the INSERT policy's WITH CHECK re-derives membership and role server-side |
