<objective>
Close G-05-4: the "latest DG per animal" tie-breaker must be `exam_date`, not `created_at`.

A-DG-ORDER was an open domain question since 05-RESEARCH.md; the veterinarian resolved it in
05-UAT.md test 4: **"fix — use exam_date, not created_at, as the DG tie-breaker"**. The original
(now-overruled) assumption was that `examDate` was untrustworthy because D-11 lets a vet set it
per animal — so three separate reduction loops were written against `createdAt` instead.

The UAT's `isolated_to` note named two sites. There are **three**. The third
(`_DgSectionState._mostRecentDg`) was uncataloged, and 05-02-SUMMARY.md wrongly claimed the
tie-breaker was "already isolated, no callers to touch". That third site is the highest-stakes
one: it drives both the chip preselection and the result carried forward into the
`save_dg_records` payload for observation-only rows.

Purpose: with the wrong tie-breaker, a reexam correction entered later for an earlier exam date
silently overrides the true latest diagnosis — misreporting % prenhez and the ficha's last DG in
exactly the D-12 reexam scenario the feature exists to serve.
Output: one shared, unit-tested comparison function; three call sites converted to it; the stale
A-DG-ORDER rationale removed from four doc comments so it cannot be "restored" by a later reader.
</objective>
