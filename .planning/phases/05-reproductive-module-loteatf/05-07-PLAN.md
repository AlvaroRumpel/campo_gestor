<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Animal id in the URL → history query | The animal id is attacker-controllable; the history it yields spans ATFs the caller may not be entitled to see |
| `registerBaixa` call → animals table | The reason, date, and observation are all client-supplied; the call previously reached the table directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-36 | Information Disclosure | Reproductive history revealing ATF names or DG results from a property the user is not a member of | high | mitigate | `members_can_read_atf_memberships`, `members_can_read_dg_records`, and `members_can_read_atf_batches` (05-01) all gate on `is_member_of`; the embedded reads inherit them |
| T-05-37 | Elevation of Privilege | A reader or owner registering a baixa, which the old direct UPDATE path allowed if the animals UPDATE policy was permissive | high | mitigate | `register_baixa` (05-03) re-checks `get_role(...) = 'veterinarian'` and raises 42501 before touching the row |
| T-05-38 | Tampering | A baixa registered with a reason outside the three allowed values | medium | mitigate | `register_baixa` raises SQLSTATE 22023 on an unrecognised reason (05-03) |
| T-05-39 | Tampering | Two concurrent baixas on the same animal both reporting success and double-writing the audit fields | medium | mitigate | The RPC's `deleted_at IS NULL` predicate plus `IF NOT FOUND` re-check (05-03) |
| T-05-40 | Tampering | A DG recorded from the ficha, widening the write surface D-13 deliberately narrowed | medium | mitigate | The section is a `ConsumerWidget` with no mutation call; the acceptance criteria and a widget test both assert the absence of any interactive control |
| T-05-41 | Repudiation | An animal's participation in an ATF disappearing from history after its baixa | high | mitigate | `trg_animals_baixa_deactivates_atf` (05-01) sets `active = false` and never deletes; the history query deliberately includes inactive memberships |
</threat_model>
