name for the AppBar context. It is pushed with `Navigator.push(MaterialPageRoute(...))`, not
registered as a GoRoute — it is a transient selection workflow with no deep-link requirement

  Choosing a lot pre-checks every eligible animal in it (D-06).

  `eligibleAnimalsForAtfProvider(atfId)` filtered client-side to the chosen lot. A row whose

  38-percent-alpha disabled treatment — and a title reading the animal number prefixed with a hash,

  "already in ATF" followed by the blocking ATF's name, exactly as the Copywriting Contract's
  disabled-row row specifies. Never omit such a row; its visibility is the SC-2 "mensagem clara".
- When the chosen lot yields zero eligible animals, render the inline message "Nenhuma vaca ou
  novilha neste lote." in place of the checklist while keeping the avulsos section usable.
- A `Divider` and the section label "Avulsos" in `titleMedium`.
- The debounced search field and category `FilterChip` row copied from `AnimaisScreen`, with the
  category choices restricted to the two eligible ones so a touro or terneiro can never be surfaced
  here (D-09). Matching animals from any lot render as the same `CheckboxListTile` rows with the same
  disabled treatment.
- A bottom sticky bar showing the live selection count in `bodyMedium` and a `FilledButton`
  "Adicionar animais", disabled at zero selections with the validation copy "Selecione ao menos 1
  animal".

The whole screen must work at a 360px viewport with no horizontal scroll — it is full-screen rather
than a dialog precisely because the search, filters, and long checklist do not fit `AlertDialog`
real estate.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checkbox selection → `add_animals_to_atf` payload | The client controls the id list entirely; a hand-crafted call could name any uuid |
| Client eligibility filter → business rule | The picker's category filter and disabled rows are usability, never enforcement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-29 | Tampering | Submitting a touro's id in the add payload, bypassing the UI category filter | high | mitigate | `trg_atf_membership_valid` (05-01) raises SQLSTATE 23514 on any category outside the eligible pair, on every access path |
| T-05-30 | Tampering | Submitting an animal that is already active in another ATF | high | mitigate | `animal_atf_memberships_active_idx`, the Phase 2 partial unique index, raises 23505; the disabled row is only the friendly first line |
| T-05-31 | Tampering | Submitting an animal id belonging to another property | high | mitigate | `trg_atf_membership_valid` compares the animal's `property_id` against the membership's derived value (05-01) |
| T-05-32 | Elevation of Privilege | A reader or owner adding or removing animals by calling the RPC directly | high | mitigate | Both RPCs re-check `get_role(...) = 'veterinarian'` and raise 42501 (05-03); the hidden buttons are cosmetic |
| T-05-33 | Tampering | Removing an animal that already has a DG, erasing evidence that it was examined | high | mitigate | `remove_animal_from_atf` raises 23514 when a `dg_records` row exists for the pair (05-03); the UI additionally hides the affordance |
| T-05-34 | Information Disclosure | `blockedByAtfName` revealing an ATF name from another property | medium | mitigate | The eligibility query is property-scoped and the embedded `atf_batches` read is subject to `members_can_read_atf_batches` (05-01, 05-02) |
| T-05-35 | Denial of Service | A very large base lot rendering thousands of checkbox rows | low | accept | `ListView.builder` lazily renders; the search and filter row is the narrowing tool (05-UI-SPEC E3 overflow, a locked user decision) |
</threat_model>
