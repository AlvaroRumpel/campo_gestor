# Phase 6 — Sanitary Module (Snapshot): UI Design Contract

> Visual and interaction contract for dose cadastro, sanitary application registration with
> frozen snapshot, per-lot and per-animal sanitary history, and estorno (reversal) of a
> mis-registered application.
> Generated by gsd-ui-researcher. Source of truth for gsd-planner, gsd-executor, gsd-ui-checker, gsd-ui-auditor.

## Spacing Scale

Phase 3/5 baseline scale, unchanged. Verified against `atf_animal_selection_screen.dart`,
`atf_detail_screen.dart`, `lote_detail_screen.dart`, `animais_screen.dart`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tight inline spacing |
| sm | 8px | Between form fields, KvRow separators, chip `spacing`/`runSpacing` |
| md | 16px | Card padding, dialog content vertical breaks, `ListView` outer padding |
| lg | 24px | Empty state vertical rhythm |
| 2xl | 32px | Empty state outer padding |
| 3xl | 48-64px | Empty state icon size (size token, not spacing) |

**Dialog width tokens (established, reused verbatim):**
- 480px — `AlertDialog` with several form fields: `AplicacaoFormDialog`, `DoseFormDialog`, `ResumoAplicacaoDialog`
- 400px — confirmation-only dialogs: `EstornarAplicacaoDialog`

Exceptions: none new this phase. `SanitaryAnimalSelectionScreen` checkbox rows use the
default `CheckboxListTile` touch target (~48dp) — no raised touch-target exception is needed
(unlike Phase 5's DG chip mass-entry screen, which is a rapid multi-tap grid; this is a single
tap per row, same interaction shape as `AtfAnimalSelectionScreen`, which needed no exception
either).

## Typography

Material 3 `TextTheme` roles only — never hard-code font sizes. Matches Phase 3/4/5 contract
exactly (no new roles introduced).

| Role | Flutter TextTheme | Size | Line Height | Weight | Usage in Phase 6 |
|------|-------------------|------|-------------|--------|-------------------|
| Body | `bodyMedium` | 14sp | 1.43 (M3 default) | 400 | Secondary lines (subtitle text, muted labels), dialog explanation text |
| Label | `bodyLarge` | 16sp | 1.50 (M3 default) | 400 (600 for numeric/name emphasis) | List item primary text, animal number `#N` (w600), dose name (w600) |
| Heading | `titleMedium` | 16sp | 1.50 (M3 default) | 500/600 | Section labels ("Composição", "Doses cadastradas"), card titles, dialog titles |
| Display | `headlineSmall` | 24sp | 1.33 (M3 default) | 400 | Not used — no full-page display headers introduced this phase |

Line heights are Material 3 `TextTheme` defaults — never override `height:` on any of these roles.

**Computed-field emphasis (new this phase, SANI-01 "campo não editável"):** the derived
`dosagem_por_ua` / `custo_por_ua` fields in `DoseFormDialog` and the dose list use `bodyMedium`
in `colorScheme.primary` (not the default `onSurface`) to visually distinguish "this value is
calculated, not entered" — same visual language as the % prenhez indicator in Phase 5
(`colorScheme.primary`, `bodyLarge` w600 for the headline figure; `bodyMedium` here since these
are secondary fields, not the screen's headline number).

## Color

All colors derive from `ColorScheme.fromSeed(seedColor: Color(0xFF4A6741))`. No new seed, no
hex literals except where a semantic status color is hardcoded, following the exact precedent
set in `AnimalInfoCard`'s status badge (Phase 3) and the DG chip mapping (Phase 5).

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` | Scaffold background — `SanitarioScreen`, `AplicacaoDetailScreen`, `SanitaryAnimalSelectionScreen` |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | Cards (aplicação header card, dose list cards, application summary cards) |
| Accent (10%) | `colorScheme.primary` | See explicit reserved-for list below |
| Destructive | `colorScheme.error` | Estorno action + "Estornada" status treatment only |

**Accent (`colorScheme.primary`) reserved for — explicit list:**
1. FAB on `SanitarioScreen`: "Registrar aplicação" (Aplicações tab) / "Nova dose" (Doses tab) — both role-gated veterinarian
2. `FilledButton` primary actions: "Salvar dose" (`DoseFormDialog`), "Continuar" (`AplicacaoFormDialog` submit, `SanitaryAnimalSelectionScreen` confirm), "Registrar aplicação" (`ResumoAplicacaoDialog` final confirm)
3. Active `NavigationRail`/`NavigationBar` destination indicator (unchanged, existing)
4. Active `TabBar` indicator on `SanitarioScreen` (Aplicações / Doses)
5. Selected `FilterChip`/dropdown-selected state in the filters row (reused pattern from `/animais` per D-26)
6. `LinearProgressIndicator` / `CircularProgressIndicator` during RPC calls
7. Computed-field text (`dosagem_por_ua`, `custo_por_ua`) — see Typography note above
8. Total UA / total volume figures in headers and summaries (mirrors % prenhez's use of primary for the "this number is the point of this screen" figure)

**Destructive (`colorScheme.error`) reserved for — explicit list:**
1. "Estornar aplicação" button on `AplicacaoDetailScreen` (`OutlinedButton` with `foregroundColor: colorScheme.error`, matching `AnimalInfoCard`'s "Dar baixa" `TextButton` precedent)
2. `EstornarAplicacaoDialog`'s `FilledButton` "Estornar" (this dialog IS the one destructive confirm in this phase — unlike Phase 5's "Encerrar"/"Remover", which deliberately used primary because those are routine corrections; estorno negates a real-world sanitary record and is auditable-but-permanent, closer to "Dar baixa" than to "Encerrar ATF")
3. "Estornada" status badge: `colorScheme.errorContainer` / `onErrorContainer` (reuses the exact tokens `AnimalInfoCard` already uses for "Arquivado" — negative/voided status, not a delete-action trigger)

**Neutral tertiary usage:**
- "Estorno" badge (a row that IS itself a reversal record, distinct from a row that WAS reversed): `colorScheme.surfaceContainerHigh` / `onSurface` — neutral informational tag, mirrors the "Encerrado" badge convention (a state, not a warning)
- Duplicate-application warning box in `ResumoAplicacaoDialog` (D-34): `colorScheme.tertiaryContainer` / `onTertiaryContainer` — mirrors the Phase 5 "Ainda há N sem DG" warning tone

**Accent must NOT appear on:** regular `ListTile`/`Card` borders, `AppBar` background, secondary
actions (`TextButton`, `OutlinedButton` other than the reserved destructive one above), the
"Mostrar estornadas" / "Mostrar arquivadas" toggles (default `Switch`, no primary override —
matches "Mostrar arquivados"/"Mostrar encerrados").

## Screen Inventory

### 1. SanitarioScreen (replacement — `/sanitario` shell branch, D-16)

**Purpose:** Whole sanitary module in two tabs — Aplicações (SANI-04, global list) + Doses
(SANI-01, cadastro). Replaces the placeholder at
`lib/features/sanitario/presentation/sanitario_screen.dart`.

**Layout:**
```
AppBar: "Sanitário" + TabBar ["Aplicações", "Doses"]
Body: TabBarView
  Tab 1 — Aplicações:
    ├── Filter row (horizontal scroll): Lote dropdown, Dose dropdown,
    │     "Período" OutlinedButton.icon(Icons.date_range) opening showDateRangePicker
    │     (clears via trailing IconButton(Icons.close) once a range is set)
    ├── "Mostrar estornadas" toggle row (Switch, right-aligned) — same pattern as
    │     "Mostrar arquivados"/"Mostrar encerrados"
    └── Expanded: ListView.builder(AplicacaoCard) or empty state
  Tab 2 — Doses:
    ├── "Mostrar arquivadas" toggle row (Switch, right-aligned)
    └── Expanded: ListView.builder(DoseCard) or empty state
FAB: changes per active tab —
  Aplicações tab: "Registrar aplicação" (Icons.medical_services, opens AplicacaoFormDialog
    with no lote pre-filled — D-17 "de dois lugares")
  Doses tab: "Nova dose" (Icons.add, opens DoseFormDialog)
  Both role-gated veterinarian (absent, not disabled, for owner/reader — established _canEdit pattern)
```

**AplicacaoCard** (mirrors `_AtfCard` structure):
- `Card` with `colorScheme.surfaceContainerHighest`, padding `EdgeInsets.all(16)`
- Title line: dose name, e.g. `"Ivomec Gold"` (`bodyLarge`, weight 600)
- Trailing badge (mutually exclusive):
  - `"Estornada"` chip (`errorContainer`/`onErrorContainer`) if this application has a reversal
  - `"Estorno"` chip (`surfaceContainerHigh`/`onSurface`) if this row itself is a reversal record (`reverses_application_id` set)
  - neither, if a normal, un-reversed application
- Subtitle line: `"applied_at DD/MM/AAAA · lote_name · N animais · X,X UA"`, appending `" · R$ Y,YY"` only when the frozen `total_cost` is non-null (D-11 — never render "R$ 0,00")
- `onTap` → `context.go(AppRoutes.aplicacaoDetail(app.id))`

**Empty state — no applications at all:**
- Icon: `Icons.medical_services_outlined`, size 64, `onSurface` 30%
- Heading: `"Nenhuma aplicação registrada"` (`titleMedium`)
- Body: `"Registre uma aplicação sanitária em um lote."` (`bodyMedium`, `onSurface` 60%)

**Empty state — filters/toggle produce zero results (data exists elsewhere):**
- Same icon/size, heading `"Nenhuma aplicação encontrada"`, body `"Tente ajustar os filtros."`

**DoseCard:**
- `Card`, padding 16
- Title line: `"Ivomec Gold"` (`bodyLarge` w600), princípio ativo below in `bodyMedium` `onSurface` 60% if present, e.g. `"Ivermectina + Clorsulon"`
- Values row (`Wrap`, spacing 8): `"1 mL/kg"` (dosagem, `bodyMedium`), `"400 mL/UA"` (computed, `bodyMedium` primary), and — only if `custo_por_kg` present — `"R$ 8,50/kg"` (`bodyMedium`) + `"R$ 3.400,00/UA"` (computed, `bodyMedium` primary)
- Trailing (veterinarian only): edit `IconButton(Icons.edit, tooltip: 'Editar dose')` + archive/unarchive `IconButton(Icons.archive_outlined / Icons.unarchive_outlined, tooltip: 'Arquivar dose' / 'Reativar dose')`
- Archived doses (only visible when toggle on): row rendered with `onSurface` 38% alpha (Flutter automatic disabled treatment) + trailing `"Arquivada"` chip, matching the `_ArchiveBadge` convention from `AnimaisScreen`

**Empty state — no doses at all:**
- Icon: `Icons.science_outlined`, size 64, `onSurface` 30%
- Heading: `"Nenhuma dose cadastrada"`
- Body: `"Cadastre uma dose para registrar aplicações sanitárias."`

### 2. DoseFormDialog (new — modal dialog, create AND edit, SANI-01)

**Purpose:** Cadastro/edição de dose (D-11..D-15). `valor_por_ua` fields are computed live and
non-editable (SC-1 literal requirement).

**Dialog width:** 480px, `AlertDialog` pattern matching `AtfFormDialog`/`LoteFormDialog`.

**Form fields (in order):**
1. **Nome comercial** — `TextFormField`, required, autofocus. Label `"Nome comercial *"`.
2. **Princípio ativo** — `TextFormField`, optional. Label `"Princípio ativo"`.
3. **Dosagem (mL/kg)** — `TextFormField`, `FilteringTextInputFormatter` for decimals (pt-BR comma via `intl`), required. Label `"Dosagem (mL/kg) *"`.
4. **Dosagem por UA (calculado)** — read-only `TextFormField(enabled: false)`, live-updates as field 3 changes (`× properties.kg_per_ua`, default 400 per D-12), text styled `colorScheme.primary`. Label `"Dosagem por UA (calculado)"`.
5. **Custo (R$/kg)** — `TextFormField`, `FilteringTextInputFormatter` for decimals, optional. Label `"Custo (R$/kg)"`.
6. **Custo por UA (calculado)** — read-only `TextFormField(enabled: false)`, live-updates, primary-tinted, hidden entirely when field 5 is blank (not shown as "R$ 0,00" — D-11). Label `"Custo por UA (calculado)"`.

**Actions:**
- `TextButton` "Cancelar"
- `FilledButton` "Salvar dose" (disabled during save, inline `CircularProgressIndicator(strokeWidth: 2)` — matches `AnimalEditDialog`/`LoteFormDialog` pattern)

**On success:** `SnackBar` "Dose salva." Providers invalidated: dose list provider.
**On error:** `"Não foi possível salvar a dose. Verifique os dados e tente novamente."` shown below the actions, dialog stays open with input preserved.

### 3. AplicacaoFormDialog (new — modal dialog, header step of the registration flow)

**Purpose:** Collects lote + dose + data before handing off to the full-screen animal selection
(D-06 discretion — this dialog exists because `AtfFormDialog` proved the "header dialog, then
push a full-screen selector" split works for AtfAnimalSelectionScreen; SANI-03's default-all
selection needs a resolved lote to load its active animals). Serves both entry points (D-17):
opened from `LoteDetailScreen`'s "Registrar aplicação" button with `lotId` pre-filled and
**locked** (dropdown disabled, shown as plain text instead — the lot is already resolved, no
picker needed), or from the `SanitarioScreen` FAB with the lot dropdown open for selection.

**Dialog width:** 480px, `AlertDialog` pattern.

**Form fields (in order):**
1. **Lote** — if `lotId` param provided: plain `Text(lot.name)` row (not editable). Else: `DropdownButtonFormField<String>`, required, items = active lots with at least 1 active animal (mirrors the D-18 gate — a lot with zero active animals cannot be a target). Label `"Lote *"`.
2. **Dose** — `DropdownButtonFormField<String>`, required, items = active (non-archived) doses of the property, each formatted `"[nome] — [princípio ativo]"` or just `"[nome]"` if no princípio ativo. Label `"Dose *"`.
3. **Data da aplicação** — `TextFormField` with date picker suffix icon (`showDatePicker`), required, format `DD/MM/AAAA`, default today (D-06). Label `"Data da aplicação *"`.

**Actions:**
- `TextButton` "Cancelar"
- `FilledButton` "Continuar" (disabled until lote+dose+data are all set; navigates to `SanitaryAnimalSelectionScreen` via `Navigator.push`, does NOT write to the database — no spinner needed, this is pure client-side navigation)

### 4. SanitaryAnimalSelectionScreen (new — full-screen, pushed via `Navigator.push`, SANI-02/03, D-21)

**Purpose:** Implements D-21/D-22/D-33 — full-screen checklist of the chosen lote's active
animals, all pre-checked by default (SANI-03), individual deselection, live counter. Mirrors
`AtfAnimalSelectionScreen`'s structure but single-lote (no "lote base" picker — the lote is
already resolved by `AplicacaoFormDialog`) and no avulsos section (application composition is
always the chosen lote, per SC-2).

**Layout:**
```
AppBar: leading IconButton(Icons.close) [confirms discard if any deselection was made —
        reuse the "Descartar seleção?" AlertDialog verbatim from AtfAnimalSelectionScreen]
        title: Column [ "Selecionar animais", subtitle: lote.name (bodySmall) ]
Body (Column):
  ├── Expanded: ListView.builder(CheckboxListTile) — one row per active animal
  │     (deletedAt IS NULL, D-22), all pre-checked by default
  └── Bottom sticky bar: "N de M selecionados · X,X UA" (bodyMedium, live) +
        FilledButton "Continuar" (disabled when 0 selected)
FAB: none (bottom sticky bar replaces it, same as AtfAnimalSelectionScreen)
```

**Row format:** `CheckboxListTile`, title `"#42 · Vaca"` (`bodyLarge`, number w600 via `TextSpan`, same as `_AnimalList` row style).

**Live counter (exact copy per D-21):** `"47 de 50 selecionados · 42,5 UA"` — updates the UA
figure as checkboxes toggle, `bodyMedium`.

**Empty state — lote resolved but zero active animals:** cannot occur in normal flow (D-18 gate
+ the D-17 dropdown filter both exclude zero-animal lots before reaching this screen); if the
composition changed to zero between opening the dialog and this screen (race), fall back to the
D-32/D-33 recovery path below rather than a distinct empty state.

**On "Continuar":** does NOT call the RPC. Pushes `ResumoAplicacaoDialog` (as a `showDialog`, or
navigates forward — Claude's discretion: implemented as `Navigator.push` to a screen wrapping
the dialog content full-width would break the "resumo antes do INSERT" intent of a *confirming*
step; use `showDialog` here, keeping the selection screen underneath so "Voltar" from the
summary returns to the exact same checklist state).

**On concurrency conflict (D-32/D-33 — server rejects at final confirm, not here):** see
`ResumoAplicacaoDialog` below for the full recovery contract; this screen's role is only to
re-render with animals that left the lote removed and newly-active animals added (pre-checked),
preserving the user's existing deselections for animals still present.

### 5. ResumoAplicacaoDialog (new — modal dialog, confirm-before-INSERT step, D-23/D-34/D-35/D-36)

**Purpose:** The single confirmation gate before the irreversible INSERT (SANI-02, SC-3). Shows
totals, a permanence warning, and — when a matching recent application is detected (D-34) — an
extra-confirmation warning box.

**Dialog width:** 480px.

**Content (in order):**
1. Title: `"Confirmar aplicação"`
2. KvRows (same `_KvRow` pattern, label width 120): Dose, Lote, Data
3. Totals block (`bodyLarge` w600, `colorScheme.primary` for the numbers): `"N animais · X,X UA"`, `"Volume total: Y mL"` (or `"Y,Y L"` when ≥1000 mL), and `"Custo total: R$ Z,ZZ"` only when the dose has a non-null cost (D-11)
4. If any animals were deselected: muted line `"M animal(is) desmarcado(s)."` (`bodyMedium`, `onSurface` 60%)
5. Permanence warning (always shown): `Container` styled as an inline notice, `colorScheme.surfaceContainerHigh` background, `Icons.info_outline` leading, text `"Este registro é permanente e não pode ser editado ou apagado depois de confirmado."` (`bodyMedium`)
6. **Duplicate-detection warning (D-34, conditional):** when a recent identical application (same dose + lote + data) is detected, a `Container` with `colorScheme.tertiaryContainer`/`onTertiaryContainer`, `Icons.warning_amber` leading, text `"Uma aplicação idêntica (mesma dose, lote e data) já foi registrada recentemente. Confirmar mesmo assim?"` + a `CheckboxListTile` "Sim, registrar mesmo assim" that must be checked to enable the final confirm button. This is the "segunda confirmação" resolved client-side (D-34 — no server block, no unique index for this case).
7. **Inline error slot (D-35/D-36, conditional):** when the RPC call fails, the mapped pt-BR message from `SanitaryApplicationException` renders here (`colorScheme.error` text) with a `TextButton` "Recarregar" beside it — tapping it pops this dialog AND the `SanitaryAnimalSelectionScreen`, re-pushing a freshly reloaded selection screen per D-32/D-33 (preserves still-valid deselections, drops departed animals, pre-checks newly-active ones). SnackBar is reserved for success only (D-36).

**Actions:**
- `TextButton` "Voltar" (pops this dialog only, returns to `SanitaryAnimalSelectionScreen` with selection intact)
- `FilledButton` "Registrar aplicação" — disabled while saving (inline spinner) AND disabled when the duplicate-confirmation checkbox (item 6) is required but unchecked. Double-tap guarded by disabling during the in-flight call (D-34).

**On success:** dialog + selection screen both pop back to the origin (`SanitarioScreen`'s
Aplicações tab, or `LoteDetailScreen` — whichever opened `AplicacaoFormDialog`, D-24). `SnackBar`:
`"Aplicação registrada — N animais"` (exact copy, D-24). Providers invalidated: application list
(global + by-lote), the affected lote's sanitary history section, and every selected animal's
`sanitaryHistoryByAnimalProvider` if that animal's ficha happens to be open.

### 6. AplicacaoDetailScreen (new — `/aplicacoes/:id` root-level GoRoute, D-19)

**Purpose:** Read-only detail of a single frozen application, plus the veterinarian-only estorno

context.pop(); else context.go(AppRoutes.sanitario);` — this route is reachable from three
different list origins (global list, lote history section, animal ficha), so it cannot assume a
push stack always exists.

**Layout:**
```
AppBar: dose_name + back button (resolved-fallback above)
Body (ListView, padding: EdgeInsets.all(16)):
  ├── AplicacaoHeaderCard
  ├── SizedBox(height: 16)
  ├── if (skipped_count > 0): muted note "N animal(is) desmarcado(s) nesta aplicação."
  ├── SizedBox(height: 16)
  └── _CompositionListSection ("Composição", N animais)
```

**AplicacaoHeaderCard:**
- `Card`, `colorScheme.surfaceContainerHighest`, padding 16
- Row: `[icon Icons.medical_services_outlined]` `[dose_name, titleMedium]` `[Spacer]` `[status badge: "Estornada" / "Estorno" / none — same mapping as AplicacaoCard]`
- KvRows (`_KvRow`, label width 120): Lote (nome congelado; tappable → `/lotes/:id` if the lot still exists and is not soft-deleted, else plain muted text — the name is the source of truth regardless), Data da aplicação, Dosagem aplicada (`"[dosagem_por_kg] mL/kg ([dosagem_por_ua] mL/UA)"`), Custo (`"R$ [custo_por_kg]/kg (R$ [custo_por_ua]/UA)"`, row entirely omitted if the dose had no cost at capture time), Observação (if present)

- **If this row is a reversal** (`reverses_application_id` set): additional KvRow "Estorno de" → tappable link to the original application (`/aplicacoes/:originalId`)
- **If this row has been reversed**: additional KvRow "Estornada em" → date + tappable link to the reversal row
- **Estorno action** (veterinarian only, D-30): `OutlinedButton.icon(Icons.undo, "Estornar aplicação", foregroundColor: colorScheme.error)`, rendered only when this row is NOT itself a reversal AND has not already been reversed (absence, not disabled, per the established role-gate convention — D-31's unique-reversal guarantee is enforced by the DB; the RPC returns a legible "já estornada" error as a defense-in-depth backstop if a race slips through)

**_CompositionListSection:**
- Header: `"Composição"` (`titleMedium`) + `"(N animais)"` muted
- `ListView.builder(shrinkWrap: true, physics: NeverScrollableScrollPhysics())` — one row per
  animal in the frozen `composition_snapshot` array: `"#[number] · [category] · [ua] UA"`
  (`bodyLarge`, number w600), `onTap` → `context.go(AppRoutes.animalDetail(animal_id))` (the
  live animal record — the row itself shows only the frozen number/category/UA, never a live
  re-fetch, per D-02's immutability intent)

### 7. EstornarAplicacaoDialog (new — modal confirmation dialog, D-27..D-31)

**Purpose:** The one destructive-toned action in this phase — creates a new, also-immutable
reversal row. Mirrors `BaixaDialog`'s structural template (required-reason confirmation).

**Dialog width:** 400px.

**Content:**
- Title: `_saving ? LinearProgressIndicator() : Text('Estornar aplicação "[dose_name]"?')`
- Body: `"Esta ação cria um novo registro que anula os efeitos desta aplicação no histórico. Ambos os registros ficam permanentes — esta ação não pode ser desfeita."` (`bodyMedium`)
- **Motivo** — `TextFormField`, `maxLines: 3`, required (D-30: "motivo obrigatório"). Label `"Motivo do estorno *"`. Validator: `"Informe o motivo do estorno"`.

**Actions:**
- `TextButton` "Cancelar"
- `FilledButton` "Estornar" (`colorScheme.error` background — the one destructive-red button in
  this phase, see Color contract above) — disabled while saving, inline spinner

**On success:** pops with `true`. `AplicacaoDetailScreen` invalidates its own provider, the
application list providers (global + lote + affected animals), and the lote's sanitary history
section. `SnackBar`: `"Aplicação estornada."`
**On error:** `"Não foi possível estornar a aplicação. Tente novamente."` shown inline below the
form, dialog stays open with the motivo text preserved. If the specific ERRCODE indicates an
already-existing reversal (D-31 race), the message is instead `"Esta aplicação já foi estornada."`
and the dialog offers a `TextButton` "Ver estorno" navigating to the existing reversal row.

### 8. LoteDetailScreen — Sanitary history section (SANI-04, D-20) + registration entry point (D-17/D-18)

**File:** `lib/features/lotes/presentation/lote_detail_screen.dart` — additive change, no

**New section, placed below `_AnimalList` (D-20 — "mesma estrutura de seção que a ficha do

_SanitaryHistorySection (Card, same outlined shell as _PlaceholderSection: outline border,

## Interaction Contracts

### Role Gate
- FAB on `SanitarioScreen` (both tab variants): visible only when `role == 'veterinarian'`. Same `_canEdit` pattern as Phases 3–5.
- Dose edit/archive icons, "Registrar aplicação" button (`LoteDetailScreen`), "Estornar aplicação" button: all absent (not disabled) for non-veterinarian roles.
- `SanitaryAnimalSelectionScreen`, `AplicacaoFormDialog`, `ResumoAplicacaoDialog`, `EstornarAplicacaoDialog`: only reachable via a role-gated entry point, so no additional in-screen role check is needed — a reader/owner never reaches them through the UI. The RPC re-validates the role server-side regardless (D-35, ERRCODE 42501), same defense-in-depth posture as every write RPC since Phase 4.

### Navigation
- `/aplicacoes/:id` is a root-level `GoRoute` (D-19), added to `AppRoutes` as `aplicacaoById = '/aplicacoes/:id'` template + `static String aplicacaoDetail(String id) => '/aplicacoes/$id'` helper — mirrors `loteById`/`loteDetail` and `atfById`/`atfDetail`.
- `SanitaryAnimalSelectionScreen` is pushed via `Navigator.push`, not a GoRoute — no deep-link requirement, transient workflow (mirrors `AtfAnimalSelectionScreen`).
- `AplicacaoFormDialog`, `DoseFormDialog`, `ResumoAplicacaoDialog`, `EstornarAplicacaoDialog`: all `showDialog`, not routes.
- Sanitary history rows (global list, lote section, animal ficha) all navigate via `context.go(AppRoutes.aplicacaoDetail(id))`.
- Back button: `context.pop()` for GoRouter routes generally; `AplicacaoDetailScreen` uses the resolved-fallback pattern (`canPop() ? pop() : go(sanitario)`) because it has three possible origins, mirroring `LoteDetailScreen`'s existing fallback logic. `Navigator.pop()` for the pushed selection screen.

### Forms
- All dialogs (`DoseFormDialog`, `AplicacaoFormDialog`, `EstornarAplicacaoDialog`): `AlertDialog` pattern, `SizedBox` width constraint, `LinearProgressIndicator`/inline spinner during save, `FilledButton`/`TextButton` action pair — verbatim `LoteFormDialog`/`BaixaDialog`/`AtfFormDialog` template.
- `ResumoAplicacaoDialog` deviates only in having two possible destructive-adjacent gates (permanence warning always shown, duplicate-warning conditional) before its `FilledButton` is fully enabled — everything else (spinner-on-save, inline error slot, action-pair layout) matches the template.
- Date pickers: Flutter's built-in `showDatePicker` (no new package) — format `DD/MM/AAAA` via `intl`. Period filter uses `showDateRangePicker`, also built-in.
- `ref.invalidate(...)` on every successful mutation, matching the established post-success pattern.

### Concurrency Recovery (D-32/D-33)
- The RPC revalidates every submitted `animal_id` at confirm time and aborts the whole transaction if any animal is no longer active in that lote (SC-3's "nunca meio-gravado" guarantee).
- On rejection, `ResumoAplicacaoDialog`'s "Recarregar" action pops back through the selection screen and re-fetches the lote's current active animals: animals that left the lote are removed from the list entirely; newly-active animals appear pre-checked (default); the user's prior deselections are preserved for animals still present. This is a re-render, not a full flow restart — the vet does not lose the desmarcações they already made.

### Snackbar
- Success confirmations ARE shown for every mutation in this phase (dose save, application registration, estorno) because none of these flows navigate away from a screen the vet is actively working in for the FAB-opened case, and even the lote-button case returns to `LoteDetailScreen` rather than a fresh screen — an explicit confirmation is the reliable signal. Matches the Phase 5 convention (DG save, animal-add).
- Error: same `ScaffoldMessenger` pattern as established, EXCEPT inside `ResumoAplicacaoDialog` and `EstornarAplicacaoDialog`, where the error renders inline per D-36 (SnackBar reserved for success only in those two surfaces).
