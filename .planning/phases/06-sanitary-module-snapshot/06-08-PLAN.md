    sort by number, and hold the total. On the first data arrival seed the selected-id set with every
    one of those ids — the SANI-03 default is all selected. Guard that seeding so it runs once rather
    than on every rebuild, otherwise a rebuild would silently undo the user's deselections.

    and the continue button. The counter renders the locked minimum-selection message when nothing is
    selected, and otherwise the exact locked counter format with the selected count, the total, and
    the running UA figure computed from the selected animals' categories through the shared helpers.
    The continue `FilledButton` carries the locked label and is disabled at zero selected.

    Continue handler: show `ResumoAplicacaoDialog` with the lot id, lot name, dose, date, the selected

    pops this screen and returns its animal count to the caller so the origin can show the locked
    success snackbar; a reload outcome triggers the refetch described next; null leaves the checklist
    exactly as it was.

    Reload handling for D-33: invalidate the lot's animal list provider and await its fresh value,
    then rebuild the selected-id set as the intersection of the previous selection with the new active
    ids, unioned with the new ids that were not present before — so animals that left the lot
    disappear, animals the user had unchecked stay unchecked, and newly-arrived animals come in
    pre-checked per the default. Re-seeding must not fall back to selecting everything; that would
    discard the deselection work this recovery exists to protect.
