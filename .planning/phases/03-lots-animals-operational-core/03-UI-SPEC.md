| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4). Source: established in Phase 2 code (`paddock_form_dialog.dart`, `piquetes_screen.dart`).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip spacing, inline row gaps |
| sm | 8px | List item separators, between chips, secondary spacing |
| md | 16px | Form field vertical gaps, list padding (horizontal + vertical), card content padding |
| lg | 24px | Empty state vertical rhythm, dialog section padding |
| xl | 32px | Empty state outer padding, major section breaks |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Empty state icon size (size token, not spacing) |

Exceptions:
- Touch targets for EC (1–5) chips: minimum 44px height (accessibility — mobile web)
- Batch form category quantity counter buttons: minimum 44px height (mobile tap target)
- FAB: Flutter default 56px (Material 3 standard)

## Typography

Source: Material 3 TextTheme via `ThemeData`. Established usage in Phase 2 code confirmed these roles.
All sizes are Flutter `TextStyle` `fontSize` values (logical pixels = dp).

| Role | Flutter TextTheme Style | Size | Weight | Line Height | Usage |
|------|------------------------|------|--------|-------------|-------|
| Body | `bodyMedium` | 14sp | 400 | 1.43 (M3 default) | List item secondary text, field hints, supporting labels |
| Label | `bodyLarge` | 16sp | 400 | 1.5 | List item primary text, field values, dialog body |
| Heading | `titleMedium` | 16sp | 500 | 1.5 | Empty state titles, section labels, card titles |
| Display | `headlineSmall` | 24sp | 400 | 1.33 | Screen headers (AppBar title is separate — inherits M3 titleLarge) |

**Numeric display** (UA total, animal count badges): `bodyLarge` weight 600 (semibold) via `copyWith(fontWeight: FontWeight.w600)`.

## Color

Source: `ColorScheme.fromSeed(seedColor: Color(0xFF4A6741))`. Exact generated hex values depend on Material 3 tonal palette algorithm. Use `Theme.of(context).colorScheme` accessors — never hardcode hex in widgets.

| Role | ColorScheme Token | Material 3 Alias | Usage |
|------|------------------|-----------------|-------|
| Dominant (60%) | `colorScheme.surface` | surface | Scaffold background, screen body |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | surfaceVariant | Cards (`Card` widget), list items, form field fills |
| Accent (10%) | `colorScheme.primary` | primary | FAB, FilledButton, active nav rail destination, selected chip, progress indicators |
| Destructive | `colorScheme.error` | error | "Dar baixa" action button, delete confirmations, validation error text |

**Accent reserved for (explicit list):**
- FAB ("+ Lote", "+ Animal")
- FilledButton (primary form submit: "Criar lote", "Criar animal", "Salvar")
- Active NavigationRail destination indicator
- Selected FilterChip (categoria filter active state)
- CircularProgressIndicator during batch generation
- Body Condition (EC) chip selected state

**Accent must NOT appear on:**
- Regular ListTile, Card borders, AppBar background (uses `colorScheme.surface`)
- Secondary actions (TextButton, OutlinedButton, PopupMenuItem)
- Toggle "Mostrar arquivados" (uses `colorScheme.secondary`)

**Animal status badge colors:**
- Arquivado / Vendido: `colorScheme.tertiary` surface tint (warm tone — not red)
- Arquivado / Morto: `colorScheme.onSurface` at 38% alpha (muted)
- Arquivado / Descartado: `colorScheme.onSurface` at 38% alpha (muted)
- Live / active: no badge (absence of badge = active)

## Screen Inventory

### 1. PaddockDetailScreen (expanded — `/piquetes/:id`)

**Purpose:** Shows paddock info + list of its operational lots. Phase 3 expands this existing screen.

**Layout:**
```
AppBar: "Piquete" + back button
Body (ListView):
  ├── Card: paddock info (nome, área ha, capacidade UA) — padding md(16)
  ├── SizedBox(sm=8)
  ├── Row: Text("Lotes", style: titleMedium) + spacer
  ├── SizedBox(xs=4)
  ├── ListView of LoteCards (separated by sm=8)
  └── [empty state if no lotes]
FAB: "+ Lote" (veterinarian role only — absent for owner/reader)
```

**LoteCard:**
- Leading: `Icons.group_work_outlined`
- Title: lote name (bodyLarge)
- Subtitle: `"X vacas · Y terneiros · Z UA total"` (bodyMedium, colorScheme.onSurface at 60%)
- Trailing: PopupMenuButton (Editar nome / Detalhes) — veterinarian only
- onTap → `/lotes/:id`

**Lote empty state (within PaddockDetailScreen):**
- Icon: `Icons.group_work_outlined`, size: 48, color: onSurface at 30%
- Heading: `"Nenhum lote neste piquete"`
- Body: `"Crie um lote para começar a registrar animais."`
- No CTA button (use FAB)

### 2. LoteFormDialog (new — modal dialog)

**Purpose:** Create a new operational lot with batch animal composition.
Reuses `AlertDialog` pattern from `PaddockFormDialog`.

**Dialog width:** 480px (SizedBox constraint — wider than paddock form due to category grid)

**Form sections:**
1. **Nome do lote** — TextFormField, OutlineInputBorder, required, autofocus
2. **Piquete** — read-only (pre-filled from context, not editable in creation)
3. **Composição inicial** — section label "Animais por categoria" (titleMedium)
   - 7 rows, one per category: Vacas, Novilhas, Terneiros, Terneiras, Touros, Bois, Novilhos
   - Each row: `[CategoryLabel] [DecrementButton(-)] [NumberDisplay] [IncrementButton(+)] [RacaSearchSelect]`
   - Quantity default: 0. Range: 0–999.
   - DecrementButton/IncrementButton: IconButton with `Icons.remove` / `Icons.add`, size 44px min
   - RacaSearchSelect: DropdownButtonFormField or custom search-select, optional
4. **Iniciar do número** (optional) — TextFormField, keyboardType number, hint: "Ex: 101 (deixe vazio para auto)"
5. Validation: nome required + sum of all categories > 0

**Actions:**
- TextButton "Cancelar"
- FilledButton "Criar lote" (disabled during save, shows 16×16 CircularProgressIndicator while saving)

**Batch feedback:** On submit, show LinearProgressIndicator below the dialog title while the RPC is executing (replace static title area). On completion, pop dialog with `true`.

### 3. LoteDetailScreen (new — `/lotes/:loteId`)

**Purpose:** Shows lot header + active animal list. FAB to add individual animal.

**Layout:**
```
AppBar: lote.name + back button
Body (CustomScrollView with SliverList):
  ├── SliverToBoxAdapter: LoteHeader card
  │   ├── Row: piquete name (bodyMedium, secondary color)
  │   ├── SizedBox(xs=4)
  │   └── Wrap: CategoryChips (Vacas: X · UA X.X)
  ├── SizedBox(sm=8)
  ├── SliverList: animal tiles (separated by Divider)
  └── [empty state if no animals]
FAB: "+ Animal" (veterinarian role only)
```

**LoteHeader card:**
- `Card` with `colorScheme.surfaceContainerHighest`
- Padding: md(16)
- Row: `[Icon(Icons.group_work)] [lote name, titleMedium] [Spacer] [PopupMenu]`
- Below: Wrap of `Chip` widgets per category present (e.g. "Vacas: 8 · 8,0 UA", "Terneiros: 5 · 2,5 UA")
- Total UA row: `"Total: X,X UA"` bodyLarge weight 600, right-aligned

**Animal list tile (in LoteDetailScreen):**
- Format: `#42` (bodyLarge weight 600) + `"· Vaca"` (bodyMedium) — primary line
- Secondary line: `"Raça · EC X"` if race and EC are set; otherwise empty
- onTap → `/animais/:id`
- No trailing action (actions live in animal detail screen)

**Lote empty state:**
- Icon: `Icons.pets_outlined`, size: 48, color: onSurface at 30%
- Heading: `"Nenhum animal neste lote"`
- Body: `"Use o botão + para adicionar animais individualmente."`

### 4. AnimalFormDialog (new — modal dialog, individual animal)

**Purpose:** Add a single animal to an existing lot. Triggered from LoteDetailScreen FAB.

**Dialog width:** 400px

**Form fields:**
1. **Categoria** — DropdownButtonFormField, required (Vaca / Novilha / Terneiro / Terneira / Touro / Boi / Novilho)
2. **Número** — TextFormField, keyboardType number, pre-filled with auto-generated value, overridable, hint: "Auto-gerado"
3. **Raça** — DropdownButtonFormField (search-select), optional, list hardcoded (D-14)
4. **Estado Corporal (EC 1–5)** — SegmentedButton or 5-chip row, optional. Labels: 1, 2, 3, 4, 5. No label before the row (the label is the section heading "Estado Corporal")
5. **Observação** — TextFormField, optional, maxLines: 3

**EC chip row:**
- 5 `ChoiceChip` widgets in a `Row` with `MainAxisAlignment.spaceBetween`
- Each chip: label = "1"…"5", selected = primary color, unselected = outline
- Minimum height 44px, minimum width 44px per chip (touch target)

**Actions:**
- TextButton "Cancelar"
- FilledButton "Adicionar" (disabled during save)

### 5. AnimaisScreen (replacement — `/animais`)

**Purpose:** Global animal search and filter for the active property.

**Layout:**
```
AppBar: "Animais"
Body (Column):
  ├── SearchBar (top, full width, padding: horizontal md)
  │   └── hint: "Buscar por número..."
  ├── SizedBox(sm=8)
  ├── FilterRow (horizontal scroll, SingleChildScrollView):
  │   ├── FilterChips: Todas | Vaca | Novilha | Terneiro | Terneira | Touro | Boi | Novilho
  │   ├── DropdownButton: Lote (nullable — "Todos os lotes")
  │   └── DropdownButton: Piquete (nullable — "Todos os piquetes")
  ├── SummaryBar: "X animais · Y,Y UA total" (bodyMedium, surface container)
  ├── ToggleRow: "Mostrar arquivados" (Switch widget, right-aligned)
  └── Expanded: ListView.builder (animal tiles) or empty state
```

**Animal list tile (AnimaisScreen):**
- Primary: `#42 · Vaca` (bodyLarge, weight 600 for number, bodyLarge regular for category)
- Secondary: `Lote A · Piquete Norte` (bodyMedium, onSurface 60%)
- Archived animals (when toggle on): same tile + `Chip` badge ("Vendido" / "Morto" / "Descartado") using `colorScheme.errorContainer` (sale = tertiary, death/discard = onSurface at 38% alpha). Badge at trailing position.
- onTap → `/animais/:id`

**Search behavior:** debounce 300ms, filters in-memory against loaded list (no server round-trip for typing). Clear button (X) appears when search field is non-empty.

**SummaryBar:** `Container` with `colorScheme.surfaceContainerHighest`, padding `EdgeInsets.symmetric(horizontal: 16, vertical: 8)`, row: left text, right UA badge.

**Filter chips:** `FilterChip` with `showCheckmark: false`. Active chip uses `colorScheme.primary` filled. Chips are in a horizontal `SingleChildScrollView` with `scrollDirection: Axis.horizontal`.

**Empty state (no animals match filter):**
- Icon: `Icons.search_off`, size: 48, onSurface at 30%
- Heading: `"Nenhum animal encontrado"`
- Body: `"Tente ajustar os filtros ou a busca por número."`

**Empty state (property has no animals at all):**
- Icon: `Icons.pets_outlined`, size: 64, onSurface at 30%
- Heading: `"Nenhum animal cadastrado"`
- Body: `"Crie um lote no piquete para registrar os animais da fazenda."`

## Interaction Contracts

### Role Gate
- FAB for "Novo lote" and "Novo animal": visible only when `role == 'veterinarian'`. Absent (not disabled) for owner and reader roles. Matches Phase 2 pattern (`_canEdit` check against `memberPropertiesProvider`).
- Edit actions on animal: absent for non-veterinarian. Same pattern.
- "Dar baixa" button: absent for non-veterinarian.

### Debounce
- Animal number search on `/animais`: 300ms debounce before filtering. Source: D-20.

### Batch generation feedback
- On "Criar lote" submit: replace dialog title row with `LinearProgressIndicator` (indeterminate). FilledButton becomes disabled. Show `CircularProgressIndicator(strokeWidth: 2)` inside button. On RPC return: pop dialog with `true`. On error: restore normal state, show `SnackBar` with error message.

### Archived animal visibility
- On baixa confirmation: optimistic local state change — tile shows archived badge immediately without navigation. Provider invalidated on dialog close. Source: D-21 ("não some imediatamente").

### Navigation
- `/lotes/:loteId` is a root-level GoRoute (not nested under `/piquetes`). Accessible from PaddockDetailScreen, AnimaisScreen, AnimalDetailScreen.
- `/animais/:id` is a sub-route within the `/animais` branch. Accessible via search, lot list, paddock detail.
- Back button always uses GoRouter's `context.pop()` — never `Navigator.pop()` for route-level navigation.

### Forms
- All dialogs: `AlertDialog` pattern, `SizedBox` constraint on `content` width. Source: `PaddockFormDialog` pattern.
- All text inputs: `OutlineInputBorder`. Label format: `"Campo *"` for required fields.
- pt-BR decimal: `FilteringTextInputFormatter.allow(RegExp(r'[0-9.,]'))` + `replaceAll(',', '.')` before parse. Only for float fields (area, UA). Integer fields (number, quantity) use `FilteringTextInputFormatter.digitsOnly`.
- On successful create/save: `ref.invalidate(provider)` to refresh the upstream list.

### Snackbar
- Success: not shown (navigation change serves as confirmation).
- Error: `SnackBar(content: Text('Erro ao salvar: $e'))` using `ScaffoldMessenger`. Source: Phase 2 pattern.
