# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (not greenfield):** The ficha (`lib/features/animais/presentation/animal_detail_screen.dart`) already ships end-to-end — `AnimalInfoCard`, `_ReproductiveHistorySection`, `AnimalSanitaryHistorySection`. This contract documents the **current, already-implemented visual system** (read from source, not invented) and specifies **only the deltas** this phase adds: a baixa banner (SC-4), per-DG expansion (SC-2), per-block retry (D-04), and an adaptive `_KvRow` (SC-5). Everything not called out as a delta is a locked-as-is constraint — do not restyle it.

**Hard boundary (D-37, Phase 6):** `sanitary_history_section.dart` may receive only the D-04 retry button inside its existing `error:` branches. No other line in that file changes.

Material 3 dynamic `ColorScheme.fromSeed(seedColor: 0xFF4A6741, brightness: light)` `[VERIFIED: app_theme.dart]` — not static hex. Roles map to the 60/30/10 split as follows:

| Role | ColorScheme token | Usage |
|------|--------------------|-------|
| Dominant (60%) | `colorScheme.surface` | Screen background, outlined section-card fills |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | `AnimalInfoCard` fill (the one card that's visually "raised" above the plain history cards) |
| Accent (10%) | `colorScheme.primary` / `primaryContainer` | **Reserved for:** tappable "Lote atual" / "Piquete atual" link text (underlined, `colorScheme.primary`); "Prenha" DG result chip (`primaryContainer`/`onPrimaryContainer`) |
| Destructive/semantic | `colorScheme.errorContainer` / `onErrorContainer` | "Não-prenha" DG chip; sanitary "Estornada" badge; **new this phase: the baixa banner (D-12)** |
| Third semantic (existing, not destructive) | `colorScheme.tertiaryContainer` / `onTertiaryContainer` | "Duvidosa" DG chip; ATF-encerrar banner (Phase 5 precedent — **not** reused for the baixa banner, which is `errorContainer`) |

Accent reserved for: tappable lote/piquete links, "Prenha" DG chips. Never used for section headers, body text, or non-interactive chrome.

**Delta — baixa banner (D-12/D-13):** `colorScheme.errorContainer` background, `colorScheme.onErrorContainer` text/icon, `Icons.info_outline`, `BorderRadius.circular(12)`, `padding: EdgeInsets.all(16)`, full width, positioned as the **first** child of the ficha's `ListView`, `SizedBox(height: 16)` before `AnimalInfoCard`. Same visual family as `_EncerrarBanner` (Phase 5 precedent: `Container` + rounded corners + colored fill + `Row`), but `errorContainer` instead of `tertiaryContainer` — this state is informational-about-the-past (the animal is gone), not an actionable prompt, so it carries no action button and no dismiss `IconButton`, unlike `_EncerrarBanner`.

## Layout Contract (D-21, D-08 — first-use mechanisms, no in-repo precedent)

**`_KvRow` adaptive breakpoint (locked, not "~400px reference"):**
- Source: `LayoutBuilder` reading `constraints.maxWidth` — **not** `MediaQuery.of(context).size.width`. Rationale: `_KvRow` sits inside `Card > Padding > Column` inside a `ListView`; on wider viewports the app's adaptive shell (`NavigationRail`) narrows the content column below screen width, so `LayoutBuilder`'s local constraint is the correct signal, matching RESEARCH.md Pattern 4.
- Breakpoint: `< 400` → stacked (`Column`: label above, value below, `SizedBox(height: 2)` between). `>= 400` → current row layout (`SizedBox(120, label)` + `Expanded(value)`), unchanged.
- Do not wrap `_KvRow` in `Wrap` or `IntrinsicWidth` — breaks the `LayoutBuilder` constraint (RESEARCH.md Pitfall 4).
- Verify at exactly 360px (SC-5 floor) via widget test with `tester.view.physicalSize` — first width-constrained test in this codebase; establish the harness once for reuse.

**DG expansion mechanic (D-08):**
- Use `ExpansionTile` (stdlib Material 3 widget) — not a custom `AnimatedSize` + `setState` toggle. It is the native Flutter affordance for exactly this interaction and needs zero new code beyond wiring `children:`.
- **Show the expand chevron only when `entry.dgRecords.length > 1`.** When an ATF has 0 or 1 DG, the collapsed row already shows everything there is (per D-08's own rationale: "não poluir o caso comum, que é 1 DG por ATF") — rendering an inert expand affordance for a single-DG row is one extra visual element with nothing to reveal. This is an explicit assumption, not literally spelled out in CONTEXT.md; record it as such if challenged.
- Expanded content: one sub-row per `DgRecord`, sorted descending by `examDate` (already the D-10 embed order), each formatted `"{DD/MM/AAAA} · {resultado chip} {· observação}"` — same chip coloring as the collapsed row's result chip (`primaryContainer`=Prenha, `errorContainer`=Não-prenha, `tertiaryContainer`=Duvidosa), `bodyMedium`, left-indented ~16px to read as nested under the parent row.
- Section itself (`AnimalReproductiveHistorySection`) is never collapsible (D-19) — expansion is scoped to individual ATF rows only, never the section shell.

**Retry affordance (D-04):**
- Placement: `TextButton` labeled "Tentar novamente" immediately below the existing error `Text`, inside the same `Column`, left-aligned — mirrors RESEARCH.md Pattern 3's code shape.
- Behavior: `onPressed: () => ref.invalidate(<thatBlock'sProviderFamily>(animalId))` — must invalidate the **family instance** (with the id), never the bare family, to keep blast radius to one block.
- Scope: reproductive block and sanitary block only. `AnimalInfoCard`'s lote/piquete rows keep their current silent `"—"` fallback on error — **no retry UI added there** (RESEARCH.md Open Question 2; explicit scope boundary, not an oversight).

## UI Considerations

Applicable state considerations resolved: 11 covered, 2 backstop, 1 unresolved.

> The `partial` rows below were surfaced by the ui-consideration probe (plan-phase §9.5) as an axis
> the initial pass did not name. They are load-bearing for this phase: D-02's progressive per-block
> loading and D-04's per-block retry mean a *partially* rendered dossier is the normal case, not an
> edge case.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | reproductive-history-block | ✅ covered | "Nenhum ATF registrado para este animal." (unchanged, D-20) |
| empty | sanitary-history-block | ✅ covered | "Nenhuma aplicação sanitária registrada para este animal." (unchanged, D-37 locked) |
| loading | animal-info-card, both history blocks | ✅ covered | Progressive per-block spinners (D-02) — no unified skeleton, no gating on the slowest block |
| error | reproductive-block, sanitary-block | ✅ covered | Muted error text + new "Tentar novamente" retry scoped to that block's provider family instance (D-04) |
| error | animal-info-card lote/piquete rows | ⚠ unresolved | Falls back silently to "—", no retry UI on this row this phase — explicit scope boundary (see Layout Contract); planner should carry this as a stated assumption, not silently re-derive it |
| populated | atf-row-with-multiple-dgs | ✅ covered | Collapsed row shows latest-DG summary; `ExpansionTile` reveals all DGs desc-sorted by exam date (D-08/D-10) |
| zero-one-many | ATFs per animal | ✅ covered | 0 → empty message; 1..N → one row each, no truncation (reproductive shows all, D-06 asymmetric truncation) |
| zero-one-many | sanitary applications per animal | ✅ covered | 0 → empty message; ≤10 → all shown; >10 → "Ver todas" truncation (D-06, unchanged, D-37 locked) |
| zero-one-many | DGs per ATF (new this phase) | ✅ covered | 0 or 1 DG → no expand affordance (collapsed row is already complete); ≥2 → `ExpansionTile` shown |
| overflow / long-text | lote/piquete names, long labels in `_KvRow` | ✅ covered | D-21 adaptive stacking under 400px removes the cramped fixed-width value column |
| overflow / long-text | baixa banner text (reason + date + observation) | 🧪 backstop | No `maxLines`/ellipsis specified — free-text `observation` (pre-existing + CR-01-appended baixa note) could be long; banner `Text` should wrap normally (no truncation, this is the one place the vet needs the full note) — verify no visual overflow at 360px in the D-23 widget test |
| overflow / long-text | DG observation inside expansion | 🧪 backstop | Same as above at smaller scale — verify wraps, does not truncate, at 360px |
| partial | dossier screen shell | ✅ covered | One block failing NEVER blanks the screen: the shell renders every block that resolved, each failed block owns its own error+retry in place, and there is no full-screen error state and no gating on the slowest block (D-02 + D-04) |
| partial | animal-info-card | ✅ covered | A failed lote/piquete embed does NOT withhold the animal's own data — the card still renders every animal field and degrades only the two affected rows to "—" |
| partial | reproductive-block / sanitary-block | ✅ covered | Each history block renders its own rows as soon as its own provider resolves, independently of the sibling block's state (one may show rows while the other still spins or shows an error) |
