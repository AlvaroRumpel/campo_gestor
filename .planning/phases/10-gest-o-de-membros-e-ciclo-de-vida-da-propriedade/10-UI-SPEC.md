## Spacing Scale

Declared values (must be multiples of 4), inherited unchanged from the Phase 9 system:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, chip dot spacing |
| sm | 8px | Compact element spacing, StatusChip↔label |

**Exceptions (inherited precedent, do not "fix" to the 4pt grid — matching existing screens takes priority over grid purity):** SectionCard default padding `14px`; table row `minHeight: 44px` (header/footer `36px`/`34px`); dialog padding `EdgeInsets.fromLTRB(20, 18, 20, 16)`; chip padding `9×3`/`12h×0v` (34px pill height); desktop detail panel width fixed at `380px`; row/section gaps of `6, 9, 10, 12px` throughout `ui.dart`. Phase 10 screens (Membros list, invite dialog, archive/restore) must reuse these exact values via the existing widgets rather than introduce new spacing constants.

## Layout & Interaction Contract

(Non-template addendum — Flutter-specific structural decisions needed by planner/executor, since there is no shadcn block registry to declare against.)

- **Where the UI lives:** Membros management is reached from `PropriedadesScreen`'s existing `_PropertyCard` popup menu (mirrors "Editar"/"Remover") — new item **"Membros"**, visible to vet/owner only (`canManageMembers`, analogous to `canManageExpenses`), gated by the "control absent, never disabled" convention (`role_gates.dart`). Route: `/propriedades/:id/membros`, `DetailAppBar(parentLabel: 'Fazendas')` per existing precedent.
- **Mobile (<`Breakpoints.rail`, 1024px):** `ListView` of member `ListTile`-style rows (avatar via `FarmAvatar`, name, `StatusChip` role badge, trailing `PopupMenuButton` gated by `canManageMembers`), a `SectionCard` "Convites pendentes" list below (or above, planner's call) showing pending invites for the property with a "Revogar" action, and a `FloatingActionButton.extended` "Convidar" gated the same way. Uses `showAdaptiveForm` bottom sheet for the invite form and both confirm dialogs.
- **Desktop (≥`Breakpoints.rail`):** dense table (columns: Nome/E-mail, Papel, Ações) + a fixed **380px right panel** (`AppColors.background`, `Border(left: divider)` — exact `_buildPanel` clone from `gastos_property_screen.dart`) containing a "Convidar membro" `SectionCard` CTA at top and the "Convites pendentes" `SectionCard` list below it. Matches the established master-detail shell used by Animais/Lotes/Reprodução/Sanitário/Gastos — do not introduce a different desktop pattern for this phase.
- **Arquivar/Restaurar:** lives inside `PropriedadesScreen` itself (not a new screen) — a segmented toggle or tab ("Ativas" / "Arquivadas") above the list, matching the `_PeriodChip`-style toggle already used in `GastosPropertyScreen`. Archived cards render visually muted (reuse the "arquivada esmaecida" treatment already established for sanitary applications in Phase 9) with a single "Restaurar" `FilledButton` (accent-colored, non-destructive) replacing the edit/delete popup menu.
- **Invite dialog:** `showAdaptiveForm` at `FormWidth.form` (560px) — email `TextFormField` + role `DropdownButtonFormField<String>`, footer buttons follow the `Cancelar` (flex 10, outlined) / primary (flex 14, filled) split from `PropertyFormDialog`.
- **Archive confirmation dialog:** `showAdaptiveForm` at `FormWidth.confirm` (440px) — danger icon container (`dangerContainer`/`danger`, mirrors `_confirmDelete`), body text, `TextFormField` for the typed name, confirm button disabled (`onPressed: null`) until exact match — this is the one designed exception to "never disabled" (that convention governs role-based visibility, not form-validity gating, which is standard Material practice project-wide).
