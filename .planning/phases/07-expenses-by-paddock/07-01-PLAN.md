## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → PostgREST | A signed-in user can issue arbitrary `POST`/`PATCH` against `/rest/v1/expenses` with any column payload; only RLS + triggers stand between that payload and the row |
| multi-property member → single property row | A veterinarian who is a member of two properties holds a valid JWT for both; `property_id`-only checks cannot distinguish a legitimate write from a cross-tenant one |
| migration transaction → immutable snapshot table | The D-31 backfill deliberately suspends the invariant that no code path may mutate `sanitary_applications` |
