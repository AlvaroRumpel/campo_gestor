  </read_first>
  <action>
    Create `move_animal_to_lot(p_animal_id uuid, p_lot_id uuid) RETURNS void`, LANGUAGE plpgsql, SECURITY DEFINER, SET search_path = public. Mirror move_lot_to_paddock's structure exactly, adapted animals-to-lots. Header comment: reference MOV-01 + ROADMAP SC-4 + T-4-01 (cross-property isolation), and note this supersedes the earlier D-04 "direct UPDATE via RLS" decision because RLS alone does not check the destination lot's property.

    DECLARE two locals: v_property_id uuid, v_current_lot uuid.

    Body, in order:
    1. Load the source animal: SELECT property_id, lot_id INTO v_property_id, v_current_lot FROM animals WHERE id = p_animal_id AND deleted_at IS NULL. This validates existence + active in one shot (T-4-03).
    2. If v_property_id IS NULL: RAISE EXCEPTION 'animal % not found or is archived', p_animal_id USING ERRCODE = '23503'.
    3. Membership (T-4-05): IF NOT is_member_of(v_property_id) THEN RAISE 'forbidden: not a member of property %' USING ERRCODE = '42501'.
    4. Role (T-4-02): IF get_role(v_property_id) <> 'veterinarian'::role_enum THEN RAISE 'forbidden: only veterinarians can move animals' USING ERRCODE = '42501'.
    5. No-op guard (T-4-06): IF v_current_lot = p_lot_id THEN RAISE 'animal is already in lot %', p_lot_id USING ERRCODE = '23514'.
    6. Destination cross-property + active check (T-4-01, THE SC-4 fix): IF NOT EXISTS (SELECT 1 FROM lots WHERE id = p_lot_id AND property_id = v_property_id AND deleted_at IS NULL) THEN RAISE 'lot % not found, archived, or belongs to a different property', p_lot_id USING ERRCODE = '23503'.
    7. Atomic single-row UPDATE: UPDATE animals SET lot_id = p_lot_id WHERE id = p_animal_id.

    After the function: REVOKE ALL ON FUNCTION move_animal_to_lot(uuid, uuid) FROM public; GRANT EXECUTE ON FUNCTION move_animal_to_lot(uuid, uuid) TO authenticated.

    Do NOT create new tables, columns, or RLS policies. This is one function that concentrates the validations RLS cannot express.
  </action>
