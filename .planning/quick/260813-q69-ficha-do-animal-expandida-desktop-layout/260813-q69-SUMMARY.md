## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Header desktop overflow with long lot/paddock names near 1024px**
- **Found during:** Task 2 (writing the "no overflow at the exact cutoff with long names" widget test)
- **Issue:** The header's trailing `Wrap` (badge + stats + actions) was a direct, non-flex child of the `Row`. A non-flex `Row` child receives unbounded main-axis constraints, so the `Wrap` never actually wrapped — it just kept growing horizontally, and once combined with a long Lote/Piquete name (free text, no length limit) the `RenderFlex` overflowed both horizontally (the header `Row`) and, as a knock-on effect, vertically (the outer `Column` housing header + body).
- **Fix:** Wrapped the trailing content in `Flexible` so it receives a real bounded max-width and genuinely wraps onto additional lines; added an optional `maxWidth` (with `TextOverflow.ellipsis`) to `_HeaderStat`'s value text so a single very-long Lote/Piquete name can't push the header out on its own.
- **Files modified:** `lib/features/animais/presentation/animal_detail_screen.dart`
- **Verification:** `test/widget/animal_detail_desktop_test.dart#1024x800 e 1440x900: sem overflow no corte exato com nomes longos` passes; `tester.takeException()` is `null` at both sizes.
- **Committed in:** `fe8bbb8` (separate fix commit, since it touches Task 1's already-committed file)

## Issues Encountered
- A first draft of the widget test re-pumped the same `WidgetTester` across three roles (veterinarian → reader → archived) inside one `testWidgets` block, mirroring `animais_desktop_test.dart`'s tap-interaction pattern. The `reader` re-pump did not correctly hide the action buttons even though `_canEdit` logic was correct — reusing the same `MaterialApp`/`ProviderScope` element across multiple `pumpWidget` calls with changed provider overrides is fragile with this project's Riverpod setup. Resolved by splitting into three independent `testWidgets` blocks (one full pump each), which is also this codebase's established convention (`animal_detail_screen_test.dart` never re-pumps within a test either).
